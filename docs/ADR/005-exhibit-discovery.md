# ADR-005：展品发现自动化（三层管道）

- **状态**：Accepted
- **日期**：2026-05-16
- **决策者**：项目作者（PM）
- **相关章节**：PRD §10 内容与知识源、§14.1 需求附录（新增 F-15/F-16/F-17）

## 背景

ADR-003 把"馆藏元数据 / 学术内容 / 图像"三层数据源说清楚了，但回避了一个更基础的问题：**"哪些件今天在哪个展厅" 谁来知道？**

调研确认这是行业级空白：
- 国内大陆**没有任何博物馆**公开"当前在展展品列表" API。即使故宫"数字文物库"有 186 万件，也不告诉"今天哪些在哪个展厅"。
- 馆藏（collection）≠ 在展（on display）。两者比例通常 1–5%。
- 展品会因借展、修复、轮换、改陈而每周变动。

PM 一度建议"运营带笔记本进馆手工收集"——这在 N=1 馆可行，在 N=30 馆破产。本 ADR 解决：**展品发现必须是产品的可扩展子系统，不是运营前置工作。**

## 候选方案

| 选项 | 描述 | 单馆冷启动成本 | 长期扩展性 |
| --- | --- | --- | --- |
| A. 运营手工逐馆 | 运营到馆手抄展品 + 拍展板 | 1–3 人天 | 第 30 馆破产 |
| B. 仅馆方合作 | 等馆方开放 API / 主动供稿 | 0，但每馆需月级 BD | 不可控 |
| C. 通用爬虫 + LLM 抽取 | 自动抓馆方官网/公众号/数字展厅/Wikidata，LLM 抽 schema | 几小时（管道写好后） | 高 |
| D. 仅用户众包 | OCR 展板 + 端侧识别，用户拍 → 自动入库 | 0，但 N=1 用户时不可用 | 取决于用户密度 |
| **E. C + D 组合（Tier 0/1/2）** | 通用爬虫做冷启动 50–70%，用户无感众包补到 90%+，规模化后做视觉 SLAM | 几小时 + 首位用户半天 | 同时具备冷启动可行性与长期飞轮 |

## 决策

**选 E。展品发现按三层管道实施：**

### Tier 0 · 无人冷启动（目标覆盖 50–70%）

```
[馆名]
  ↓ discover_sources.py        自动定位:官网展览页 / 微信公众号 / 数字展厅 / Wikidata Q 实体
  ↓ crawl_pages.py             通用 selectors + LLM 兜底,抓常设/特展页
  ↓ extract_exhibits.py        LLM(Haiku 级)抽 schema:展品名 + 朝代 + 馆藏号 + 展厅 + 图
  ↓ match_l3.py                与 data/sources/(海外 CC0)fuzzy match,enrich 字段
  ↓ exhibits_{museum}.json     候选清单,每条带「置信度 + 来源链」
```

四个通用源头每馆都适用：**馆方官网展览页 · 微信公众号"展览预告"推文 · 数字展厅高亮件 · Wikidata 实体 P195 关联**。LLM 抽取替代"看懂每馆 HTML"的工程成本。

### Tier 1 · 首批用户无感众包（目标 80–90%）

冷启动遗漏由用户**无意识**补全：

- **展板 OCR**：摄像头识别展板（展品名 + 馆藏号 + 断代 + 出土地是标准格式）→ match/新增
- **位置数据**：用户停留 + 拍照时间戳 → 推断展品现位置（哪展厅哪柜）
- **首位标记反馈**：某件首次被标记时回一句"你是第 1 个看到这件的"，轻量、不打卡化
- **核心约束**：用户在做他们本来就要做的事；**不出现任何"协助标注"按钮**（违反 §6 克制基因）

### Tier 2 · 规模化（目标 95%+）

- 展厅级实时图谱（哪件最近被多少人停留、是否被换展）
- 视觉 SLAM + 蓝牙信标融合 → 厘米级展品定位
- 馆方主动接入意愿出现（产品已是真实数据源，馆方有动机告知换展）

## 理由

1. **馆方不开放 ≠ 产品不能扩展**——这是认知错位破除。商业模型(B2B 授权)的姿态从"求馆方给我们数据"变成"我们已经收集了数据，请馆方背书"。
2. **展品发现 = 产品子系统，不是运营**——任何"运营前置"方案到第 30 馆破产，且违反 side project 单人产出预算。
3. **用户众包必须无感**——一旦让用户"为系统做事"，违反 PRD §6 人格、§8.2 克制式屏幕设计第 3 条（零打卡）。
4. **单馆冷启动 = 几小时**——这是能否扩展到 100+ 馆的硬阈值。LLM 抽取使得这个数字成立。
5. **与"和你一起看"基因自洽**——用户拍照本就是和文物建立关系的自然动作；产品在后台做识别与汇总，不打扰这个关系。

## 反模式（明确禁用）

- ❌ "运营带笔记本进馆手抄展品"——任何 roadmap 阶段都不出现
- ❌ "求馆方授权"作为扩展前置——馆方合作是 nice-to-have 不是 must-have
- ❌ 任何"协助标注/积分/任务"按钮——违反克制基因
- ❌ 把 Tier 0 输出当作"已经准确"直接灰度上线——必须带置信度

## 后果与风险

- **后果一**：Tier 0 需要持续 LLM 调用预算（每馆几百次抽取，Haiku 级模型可控）；需要一个"馆 → 源头" 注册表持续维护
- **后果二**：每条入库数据带"置信度 + 来源链"两字段，需要扩展 `data/sources/_schema.json`
- **风险一**：LLM 抽取错误率——高置信度入主库，中低置信度走 Tier 1 用户众包修正
- **风险二**：馆方网站改版——LLM 兜底 selectors 比固定 XPath 鲁棒
- **风险三**：反爬——尊重 robots.txt、加 UA + 限速；微信公众号走第三方 RSS 镜像
- **风险四**：N=1 用户陷阱——所以 Tier 0 必须先到 50%+ 才上线，不能依赖 Tier 1 兜底
- **风险五**：展品断代/馆藏号识别错误——展板 OCR 必须做交叉校验(与 Tier 0 库 match,不一致打标人审)
- **未来重审条件**：(1) 国内任一头部馆推出"当前在展" API；(2) Tier 0 实测覆盖率 < 30%；(3) 用户众包准确率 < 70%；(4) 中国文物云国家级平台落地
