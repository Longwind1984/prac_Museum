# ADR-001：产品形态选择「屏为主」

- **状态**：Accepted
- **日期**：2026-05-16
- **决策者**：项目作者（PM）
- **相关章节**：PRD §8 形态决策

## 背景

产品早期描述中刻意保留了形态开放性——App、Web、可穿戴、纯语音都不排除。但作为 side project 阶段需要一个**可被 demo、可被 Figma 表达**的具体形态。

## 候选方案

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| **A. 屏为主**（传统 App 形态） | demo 可执行性高、Figma 易表达、设备人人有 | 与产品灵魂"不抢文物的光"在直觉上矛盾 |
| **B. 语音为主**（耳机 + 极简屏） | 最贴合"低声说话的朋友"的隐喻、不抢视觉注意 | demo 难做、有些场景（带你看局部细节）必须有屏 |
| **C. 可穿戴**（眼镜、AR） | 想象力最大 | 硬件门槛 + 现实可用性差，side project 阶段不可达 |
| **D. 多形态并存** | 野心感 | 没有任何一种被做透，作品集看起来分裂 |

## 决策

**选择 A. 屏为主。语音作为旁路（耳机接入时自动转单耳模式）。**

## 理由

1. **可交付性**：side project 的产出物是 PRD + Figma，Figma 表达屏比表达耳机里发生的事容易一个数量级。
2. **设备触达**：核心用户（文博中度爱好者）几乎全员有智能手机，可穿戴渗透率太低。
3. **「克制 vs 屏」的张力本身是亮点**：选屏更难做出克制感，正因为难，所以做成是 PM 作品集的差异化亮点；如果选语音，"克制"几乎是免费的，反而不显功力。
4. **场景必要性**：约一半场景需要展示**文物的高清局部图**——AI 说「看这只手」时，手机屏是最直接的视觉指示器。耳机做不到。

## 必须配套的设计约束

为防止选了「屏为主」后自动滑回 Smartify / 三毛游的形态，必须用以下六条**克制式屏幕设计**反向约束（详见 PRD §8.2）：

1. 默认低亮、单点强光
2. 零滚动、零层级
3. 零 push、零红点、零徽章、零连胜
4. 黑色为底、留白巨大
5. 「合上手机」按钮
6. 耳机即转语音

## 后果与风险

- **后果**：所有 UI 决策必须先过"克制 6 条"审查；产品视觉系统会比传统 App 简陋很多，需要设计师/作者抵抗"再加点功能"的冲动。
- **风险**：屏作为主载体仍可能在某些场景（如真实馆内强光、长时间手持疲劳）不如耳机舒适。这是已知短板，留待 v2 形态实验解决。
- **未来重审条件**：(1) AR 眼镜的消费级渗透率超过 5%；(2) 用户测试反复出现「想合上手机但又怕错过 AI 提示」的张力。
