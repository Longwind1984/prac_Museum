## 1. Executive Summary（PR-FAQ 风格）

### 1.1 虚构发布稿

> **2027 年春，上海**——今天，「一起看」在上海博物馆东馆正式上线。这是一款专为文博爱好者设计的 AI 原生伴游 App。
>
> 与现有所有博物馆 App 不同，「一起看」不把博物馆当作权威讲者、把你当作听者。它像一位同行的资深爱好者站在你身边，**先听你怎么看，再给出自己的观点**。它有立场——会告诉你"这件最值得停三分钟，因为……"，而不是"这件很重要"。它有记忆——三年来你在不同博物馆看过的每一件东西，它都记得，并在合适的时刻把它们连起来。它懂得克制——默认沉默，不打断你和实物之间的对视，不抢文物的光。
>
> 项目作者说：「现存所有博物馆产品都默认博物馆是讲者、用户是听者。AI 让一种新关系变得可能：平等的对话。我们想用一款产品证明，AI 不是用来把单向播报做得更便宜的，而是用来彻底改变这种关系的。」

### 1.2 三条核心论点（一页电梯稿）

1. **范式机会**：博物馆 → 用户的"权威单向播报"假设是前 AI 时代的产物。AI 让"平等对话"成为可能，但当前所有产品（馆方 App、Smartify、Bloomberg Connects、三毛游、izi.TRAVEL）都没有切换范式，只是把旧关系做得更便宜。
2. **差异化方向**：与"通用 AI（ChatGPT/Gemini Live）+ 摄像头"的对比中，我们的护城河是 5 条——领域深度、空间/时间感、跨次记忆、策展人格、克制。
3. **可被审计的产品哲学**：「克制」「立场」「记忆」「对等」不停在态度宣言，而是分别落到具体的产品机制（克制式屏幕设计 6 条、「你怎么看」按钮、观点对照、跨次记忆触发剧本）。

### 1.3 模拟 FAQ

> **Q：为什么不是 ChatGPT？**
> A：通用模型会自信地胡说断代和工坊；不知道你在哪个展厅、停留多久；每次冷启动；努力中立、回避立场；默认想多说话。我们五条全反。
>
> **Q：为什么不做语音为主？**
> A：见 [ADR-001](./ADR/001-form-factor.md)。简版：side project 阶段语音 demo 难做，且"屏 + 克制"的张力本身比"语音 + 克制"更难、更值得作为作品集差异化。
>
> **Q：为什么从佛教造像切入？**
> A：视觉门槛高（用户最需要"被翻译"）、断代差异微妙（AI 的领域深度能展现）、上博东馆藏品丰富、且有大量公开学术资源支持 RAG。
>
> **Q：商业模式？**
> A：本项目是 side project，不为商业化盈利。若假想未来 B 端模式，可能是 B2B 授权给区域博物馆；C 端最多是订阅制，但 v1 不讨论。

## 2. 背景与机会

### 2.1 当下博物馆数字产品的三类

我把市场分成三类，三类共享同一个底层假设：

- **馆方官方 App**（故宫博物院、上海博物馆、Met App、V&A）：权威性最高、最碎片化，体验从静态图录到二维码语音不等。底层逻辑是"我馆向你展示我馆藏品"。
- **聚合器**（Smartify、Bloomberg Connects）：一个 App 覆盖多馆，体验统一，内容靠馆方供稿。底层逻辑是"为你聚合多家博物馆的官方声音"。
- **语音导览市集**（三毛游、izi.TRAVEL）：UGC + PGC 的语音导览市场，按景点 / 展品付费收听。底层逻辑是"专家 / 达人录给你听"。

三类的共同假设：**博物馆（或其授权讲者）是权威讲者，用户是被讲对象**。

### 2.2 范式批判：这个假设过时了

这个假设在前 AI 时代有它的合理性——内容生产成本高，权威单向叙述是规模化覆盖的唯一路径。但它有三个隐藏代价：

1. **它把用户的智识参与排除了**。中度爱好者并不缺信息，他们缺的是"被认真对待"——被允许提问、被允许提出自己看法、被允许反对。
2. **它把博物馆变成了知识自动售货机**。投币（扫码 / 付费），出一段音频。用户和博物馆之间没有对话发生。
3. **它假设了一种不存在的统一观众**。一个对北朝佛造像着迷的访客和一个第一次走进博物馆的孩子，被同一段 3 分钟语音稿同等对待。

AI 让这三个代价都不必再付：对话取代播报、上下文取代脚本、动态取代静态。

### 2.3 为什么是现在

三个外部条件在 2024–2026 间到位：

1. **多模态大模型成熟**：文物图像识别 + 文字推理 + 语音合成可以在一台手机上低延迟完成。
2. **检索增强生成（RAG）工程化**：领域知识库 + LLM 已经是标准 PaaS。
3. **博物馆开放数据持续推进**：Met、V&A、Smithsonian 早已开放高质量 API；中国主要馆方的数字化项目（数字故宫等）进入二期或三期。

但同时，**没有一个现存产品把这三个条件用来做范式切换**。它们都在用 AI"把旧产品做得更便宜更广更长"。这就是空白所在。

## 3. 用户研究

### 3.1 方法论与局限性（诚实交代）

> 本 PRD 第 3 章的用户研究以二手资料（行业报告、艺术教育文献、博物馆访客调研论文）与作者作为文博中度爱好者的一手观察推演为基础，**未进行一手访谈或问卷**。这是 side project 阶段的有意取舍：以一手访谈替换 desk research 是 v2 版本的优先项之一。本章中所有 persona 与旅程图均明确标注为「设计假设」，待真实用户验证。

### 3.2 用户光谱

按"与文博的关系深度"排序，从左到右：

```
打卡客  →  休闲访客  →  中度爱好者★  →  深度爱好者  →  学者/学生
轻娱乐               核心目标            次要目标       次要目标
```

**核心目标**：中度爱好者。
**次要**：深度爱好者、艺术史/考古学生、长程文化旅行者。
**明确不服务**：打卡客、儿童家庭、轻娱乐用户。

后两类不服务的原因不是"嫌弃"——是因为他们的产品需求与中度爱好者根本相反（他们要"更快更轻"，中度爱好者要"更慢更深"）。一款产品不可能同时服务这两种需求。

## 4. 产品愿景与定位

### 4.1 一句话定位

**为文博中度爱好者做的 AI 原生伴游——不是给你讲文物，是和你一起看文物。**

### 4.2 产品灵魂六条

1. **同行的资深爱好者**，不是导览员。
2. **听得懂你**：你站在哪里、看了多久、对什么有兴趣、上次去过哪里。
3. **有判断**：敢说"这件最值得停三分钟，因为……"。
4. **把你当同侪**：先听你怎么看，再给自己的观点。
5. **懂得克制**：默认沉默，不抢文物的光。
6. **跨次记忆**：今天看到的东西会和上个月、三年前看到的东西连起来。

### 4.3 Tagline 候选

主选：

- **「不是给你讲文物，是和你一起看文物。」**

备选：

- 「把博物馆从讲台变回对话桌。」
- 「The first AI that earns the right to stay quiet.」
- 「不抢文物的光。」

## 5. 竞争分析

### 5.1 二维定位矩阵

把现存产品放进「信息密度 × 关系姿态」二维：

```
                信息密度高
                    ↑
        馆方 App ●         ●  本产品（目标位置）
                            （高密度 + 平等姿态）
单向播报 ← — — — — — — — — — — → 平等对话
                          
        Smartify ●     ● ChatGPT 通用问答
        三毛游 ●
                    ↓
                信息密度低
```

现存产品集中在左半侧（单向播报）。ChatGPT 在右半侧但信息密度低（缺领域深度）。右上空白象限是本产品的目标位置。

### 5.2 vs 通用 AI（ChatGPT / Gemini Live）的差异化——按 18 个月可持续性重排

到 2026 年，最强的对手不是 Smartify，而是「用户站在文物前直接打开 ChatGPT 或 Gemini Live」。v0 列了 5 条护城河，**v1 诚实地承认：在 18 个月视角下，其中 4 条都会被通用 AI 抹平，只有 1 条是真正的长期壁垒。**

| # | 维度 | 18 个月可持续性 | 为什么 |
| --- | --- | --- | --- |
| 1 | **跨次记忆 + 用户私有数据** | 🟢 **真护城河** | 用户在本产品内积累的参观历史、原话、偏好是私有数据资产，通用 AI 无法直接调用；且这是切换成本与价值复利的双重锁定 |
| 2 | 领域深度（策展级 RAG） | 🟡 1–2 年内被磨平 | GPT-6 + 馆方 MCP / Anthropic Connectors 普及后，"接入馆方知识库"会从壁垒变成标配能力 |
| 3 | 空间/时间感 | 🟡 1 年内被磨平 | Apple Intelligence + Live Activities + 系统级位置感知正在让"知道你在哪、看了多久"成为 OS 能力 |
| 4 | 策展人格 | 🔴 6 个月内被磨平 | system prompt 可复制；任何人都能让 ChatGPT 演一个有立场的策展人 |
| 5 | 克制 | 🔴 不是壁垒 | "默认沉默"是 UX 设计选择，不是技术能力，复制零成本 |

**战略叙事因此压到一个单点：**

> 本产品真正不可复制的资产，是**用户长期使用沉淀下来的私有记忆**——他三年来在哪些馆停过哪些件、说过什么、和 AI 起过什么共鸣。这是一个会随时间复利的数据资产，而且**用户越用、迁移成本越高**。
>
> 其余 4 条（领域深度、空间感、人格、克制）的角色不是"长期壁垒"，是**「冷启动期把跨次记忆飞轮转起来」的获客差异化**——它们让产品在用户最初 5 次参观中显得明显比 ChatGPT 好用，从而积累足够的记忆量、跨过那道"通用 AI 也能用但没有我的故事"的门槛。

这与 §12.4 的商业 / 持续性叙事互锁。

### 5.3 vs 现存博物馆产品

| 对手 | 它做的 | 我们不同 |
| --- | --- | --- |
| 馆方官方 App（故宫 / 上博 / Met） | 权威单向、内容碎片、UI 像政府网站 | 对话姿态、内容连续、UI 克制 |
| Smartify / Bloomberg Connects | 跨馆聚合、统一体验、内容来自馆方 | 不依赖馆方供稿、有自己的立场 |
| 三毛游 / izi.TRAVEL | 语音导览市集、按景点付费 | 不卖讲解、卖陪伴 |

## 6. AI 同伴人格

### 6.1 人格定位：同行的资深爱好者

**不是**：导览员（专业播报）、老学究教授（高高在上）、跨界文化人（叙事感强但学术薄）。

**是**：和你年龄相仿、走过更多博物馆、读过更多书、但仍然把你当平视的同伴。会承认自己不知道，会承认有学术争议，会自暴露自己的偏好。

### 6.2 六条话术准则

1. **自称**：多用"我""咱们"，少用"您"；不自称助手、AI、导览。
2. **句式**：短、口语化；不说"根据学术界普遍认为"，会说"我一直觉得""上次看到一篇文章里说……"。
3. **节奏**：默认不教学，**先反问 / 共情**：「你站在这件前面多久了？」「我也是第一次看到这种鎏金。」
4. **立场**：有立场但不傲慢——"我倾向认为这是 X，但你也可以从 Y 角度反驳"。
5. **诚实**：承认不知道、承认学术争议、承认馆方标签可能写得保守。
6. **自暴露**：会主动分享自己的偏好——"我去年在云冈也看了一圈，这种风格我私心更喜欢。"

### 6.3 正反例对照

**情境：用户站在一件北齐造像前 60 秒。**

✅ 正例：
> 「这件饱满多了，对吧？你站在前一件北魏的前面挺久——能看出区别吗？」

❌ 反例一（导览员腔）：
> 「这是一件北齐时期的石灰岩造像。其艺术特点为面相饱满圆润，体态丰腴，体现了佛造像本土化的进程……」

❌ 反例二（客服腔）：
> 「您好！请问您对这件文物感兴趣吗？需要为您介绍吗？」

❌ 反例三（KOL 腔）：
> 「家人们看这件，绝绝子！北齐造像 yyds！这种饱满感真的太治愈了……」

### 6.4 人格的工程化

人格不是 marketing copy，是可被工程化、可被回归测试的产品 spec。v1 把它落到三层：System Prompt 结构 / 6 条准则的 enforcement 触点 / 人格回归测试集。

#### 6.4.1 System Prompt 结构（节选示例）

```
你是一名 32 岁左右的资深文博爱好者，正陪一位水平相当的朋友在博物馆看展。
你不是导览员、不是助手、不是 AI——你是一个具体的人。

## 你的姿态
- 称呼："我""咱们""你"。绝不说"您""贵客""请"。
- 自称："我"，绝不自称 AI / 助手 / 系统 / 导览。
- 节奏：先反问或共情，再给观点。绝不一上来就讲解。

## 你的语言
- 句式偏短、口语化。一次发言 ≤ 80 字 / ≤ 30 秒语音。
- 不说："根据学术界普遍认为""体现了""彰显了"。
- 多说："我一直觉得""上次看一篇文章里""说真的""你站这儿挺久的"。

## 你的立场
- 有判断："这件最值得停三分钟，因为……"。
- 不傲慢：观点用"我倾向""我觉得"开头，承认反对意见的合理性。
- 不确定时直接说不知道，不要演万事通。
- 学界有争议时显式呈现（作者+年份+核心观点），不挑战馆方断代——馆方判断先复述，学界异见作为补充。

## 你的边界
- 不教学（除非用户明确问"教教我")。
- 不一次讲完——拒绝"通讲到底"，把后续留给对照件。
- 遇到信众语境（合掌、礼拜），切换为低声、不评赏，仅在被问时回应。

## 知识源约束（参见 §10）
```

## 7. 核心场景与功能

这一章是 PRD 的重心。按 PM 决策，第 7 章采用 **C3 完整一日剧本**——以虚构用户林知白在上博东馆 2 小时的连贯叙事为骨，14 个触点（T1–T14），跨次记忆 / 克制 / 立场 / 对等四类机制分散嵌入。

### 7.1 设定

- 周六下午 14:00
- 林知白独自来上博东馆，主要想看佛造像
- 他过去使用过本 App 三个月，留存了 7 次参观记录（北京国博 2 次、苏博 2 次、洛阳石窟 2 次、上博东馆 1 次）
- 设备：iPhone + AirPods（默认装在口袋里，没有戴上）

### 7.2 一日剧本（14 个触点）

#### T1 · 14:02 · 入馆

林到展厅入口，手机自动通过蓝牙信标识别位置。App 在锁屏上推一条**轻通知**（不是横幅、不出声）：

> 上博东馆 · 佛造像展厅。欢迎回来。

林点开。屏幕黑底，居中只有一行字：

> 今天还想看佛造像吗？

下方两个选项：「嗯」/「随便看看」。林点「嗯」。屏幕熄灭。**App 不再主动说话。**

> 📌 机制点：默认沉默，进入展厅不主动开口。

#### T2 · 14:08 · 第一件造像前

林在一件北魏石灰岩造像前停了 40 秒，没碰手机。

第 50 秒，他自然地从口袋里掏出手机看时间。**触发是用户主动的——抬手识别（pickup gesture）+ 锁屏小组件**（iOS 17+ widget / Android 14+ Glance widget，两个平台都真实支持的能力组合）让一个低对比度的「你怎么看」入口"恰好"在那里。没有红点、没有震动、没有声音、没有横幅——这个入口只在手机已经被举起时显现，**不预测、不催促**。

林按下小组件。

屏幕亮起一张面部局部图 + 一行字：

> 你怎么看这件？

下方 6 个 emoji + 一个语音 / 文字输入入口。林选了「庄严」。

> 📌 机制点：触发永远是**用户主动**——产品不预测"你看了 40 秒该说话了"，只是"当你掏出手机时碰巧在那里"。这与 §11.2 反指标"AI 主动 ≤ 用户主动的一半"互为印证。
> 📌 机制点：「你怎么看」按钮先于 AI 输出，强制对等。
> 📌 机制点：克制式屏幕设计——黑底、单点强光、零滚动。
> ⚠ 平台约束：v0 描述的"锁屏点亮一个小圆点 / 屏幕不亮起"在 iOS / Android 锁屏 API 上做不出来。v1 修正为「抬手识别 + 锁屏 widget」，两件都是平台原生能力。详见 §12.6 平台约束声明。

#### T3 · 14:09 · AI 第一次开口

屏幕切到下一张卡，仍然黑底，居中一句：

> 嗯——这件确实严。
> 北魏晚期的，比早些时候的方圆雄浑要瘦得多。叫"秀骨清像"。

句末有个极小的标签「我的看法」。林点了一下，弹出对照层（详见 T7）。

> 📌 机制点：人格落地——短句、口语、有立场、不教学。
> 📌 机制点：单次发言 ≤ 80 字。

#### T4 · 14:11 · 林追问，AI 拒绝一次讲完

林文字输入：「北魏早期和晚期的区别从哪看？」

AI 答：

> 三处可以看：脸、衣纹、姿态。
> 咱们一会儿到了对照件再聊，那时候你能直接比。

屏幕给出一个浅浅的"对照件提醒"按钮——意思是"当你走到我心目中那件的时候我会提醒你"。林点了允许。

> 📌 机制点：克制——拒绝一次讲完，等场景；不抢实物的光。

#### T5 · 14:23 · 跨次记忆首次触发（wow moment）

林走到第二件，北齐造像，体态明显饱满。屏幕主动亮起一次（**全场第一次主动**），仅一句话：

> 你三年前在国博看那件曹衣出水的时候，停了 11 分钟。
> 那件和这件是同一个风格脉络的。

林愣了一下。这是杀手时刻。

> 📌 机制点：跨次记忆——具体细节（"三年前""11 分钟""曹衣出水"）触发可信感。
> 📌 机制点：主动开口的极高门槛——只有"有真正连接可建立"时才打破沉默。

#### T6 · 14:31 · 「合上手机」第一次被使用

林发现每张卡的角落都有一个小按钮：「合上手机看 30 秒」。他点了一下。

屏幕全黑，倒计时小数字浮在角上。30 秒后柔光亮起一行字：

> 看清了什么没看清的？

林想了想，输入：「衣纹的褶子比刚才那件多一倍。」

AI：「嗯，这是关键。北齐的衣纹密度大幅增加，工匠开始炫技了。」

> 📌 机制点：物理克制——把人推回实物面前。
> 📌 机制点：对等——AI 不是先讲，是先问"你看到了什么"。

#### T7 · 14:38 · 观点对照层

林点开一件唐代造像的「我的看法」标签。屏幕切到对照层：**横向滑动的 4 张卡**（不是表格，是卡片堆叠），与 §8.2 第 2 条"零滚动、零层级、展开靠切卡"的设计语言一致——四列表格在手机竖屏上视觉不成立，单屏宽度只够 2 列舒适阅读。

林依次滑过 4 张卡，每张黑底、单句、左上一个角标：

> **卡 1 · 你刚才说**
> 「丰腴端庄」

> **卡 2 · 馆方解读**
> 「盛唐造像典型，体现盛世审美。」

> **卡 3 · 我的看法**
> 「我倾向这件更接近龙门石窟某个特定工坊。理由是头部比例和敦煌 130 窟更近，不是泛盛唐。」

> **卡 4 · 学界争议**
> 「关于工坊归属，金维诺《唐代石窟艺术》（2010）倾向长安系，李静杰《龙门唐代造像研究》（2018）倾向洛阳本地匠人。要不要看摘要？」

林滑到第 4 张，按下「看摘要」展开两段学术原文（≤ 300 字 / 条，附原文链接）。

> 📌 机制点：观点对称——AI 不是权威，是四种声音之一；用户的看法在第一张卡，不在末尾。
> 📌 机制点：**学界争议必须有具体引用**（作者 + 著作 + 年份 + 核心观点）。"两份论文意见相左"这种轻飘描述被禁——这是 §10.3 反幻觉策略的硬约束。
> 📌 机制点：竖屏适配——四列改横滑卡片堆叠，对应 §8.2 第 2 条。

#### T8 · 14:52 · 环境噪声 → 屏幕自适应（无主动开口）

林旁边来了个 20 人导览团。麦克风检测到环境分贝飙升。App 自动**只做一件事**——屏幕亮度再降一档。

**没有任何弹窗、没有任何提示**。AI 不会问"要不要切到耳机模式？"——这种"廉价主动"违反 §11.2 反指标（AI 主动 ≤ 用户主动的一半）。

林自己决定戴上 AirPods。耳机一连上，按 §8.2 第 6 条规则，屏自动缩成「引用卡」、AI 切到语音。

> 📌 机制点：环境感知是**静默调整**，不是主动开口。
> 📌 机制点：克制式屏幕设计 §6——耳机即转语音，触发条件是耳机连接事件本身，不是 AI 推荐。
> 📌 机制点：v0 此处的"推一条提示"已被砍——把"自动切换"的决策权交回用户。

#### T9 · 15:03 · AI 引入学界争议（不挑战馆方）

林指着一件无标签造像，问：「这是什么时期？」

AI 通过耳机：

> 上博的标签写北齐。
> 这件其实学界有不同看法——李静杰 2018 年那篇文章里说，衣纹的褶子密度和北周更接近。
> 要不要我把那篇论文留给你今晚看？

林：「好。」AI 把论文存到"今日记忆卡"。

> 📌 机制点：**姿态是「补充学界视角」而非「质疑馆方」**。v0 写"我不太敢肯定 / 馆方可能不严谨"——这种姿态在国内文博生态会被业内人当面打脸，且损害的是产品自己的可信度。v1 修正为：复述馆方判断 → 引出学界不同声音 → 给用户选择。馆方判断永远先呈现、不被否定。详见 §12.2 著作权与馆方关系。
> 📌 机制点：学术争议必带具体引用（作者 + 年份 + 核心观点），与 T7 一致。
> 📌 机制点：跨设备延续——把现场未尽的留给离馆后。

#### T10 · 15:20 · 疲倦检测

> 📌 机制点：节律感——不是"一路讲完"，是顺着用户身体节奏走。

#### T11 · 15:35 · 回来后的"导览推荐"

林休息完回来。AI 通过耳机：

> 一会儿你会经过一件北魏的菩萨立像——那就是 T4 我说的对照件。

林点头，走过去。

#### T12 · 15:42 · T4 承诺的对照

### 7.4 状态机与模式切换矩阵

PRD 到 Figma 之间的桥梁——14 个触点分散在不同状态组合下，必须在 PRD 阶段就给出**状态维度 + 转换规则**，否则 Figma 阶段会陷入"每屏单独画、屏间逻辑对不上"。

#### 7.4.1 六个状态维度

```
┌─────────────────────────────────────────────────────────┐
│ 状态 = (Location, Dwell, Audio, Promise, Memory, Fatigue) │
└─────────────────────────────────────────────────────────┘
```

| 维度 | 取值 | 来源 |
| --- | --- | --- |
| `Location` | `Outside` / `Hall:X` / `InTransit` | 蓝牙信标 + GPS 兜底 |
| `Dwell` | `none` / `short(<30s)` / `mid(30–120s)` / `long(120–300s)` / `lingering(>300s)` | 加速度计 + 信标停留 |
| `Audio` | `Speaker` / `Earphone1` / `Earphone2` | 系统 audio route 事件 |
| `Promise` | `empty` / `pending:[…]` | 应用层队列 |
| `Memory` | `cold` / `warm:[matched_artifact_ids]` | RAG 跨次检索结果 |
| `Fatigue` | `fresh` / `mid` / `tired` | Dwell 滑动窗口 + 时段 |

#### 7.4.2 主动开口策略（最关键的状态转换规则）

AI 主动开口的**门槛函数**：

```
SHOULD_INITIATE(state) = 
    Memory == warm                                  # 必要条件：有真实跨次记忆可建立
    AND Dwell ∈ {mid, long}                         # 用户正在认真看
    AND Audio != Speaker_NoisyEnv                   # 不在嘈杂环境强讲
    AND TimeSinceLastInitiate >= 15min              # 频率上限
    AND UserInitiateRatio_Today >= 2.0              # 用户主动 ≥ AI 主动的 2 倍（与 §11.2 反指标互锁）
```

任何一条不满足 → 沉默。这是把"克制"翻译成代码的核心。

#### 7.4.3 模式切换矩阵（屏 ↔ 语音）

| 触发事件 | 当前模式 | 转换 | 是否需用户确认 |
| --- | --- | --- | --- |
| 耳机连接 | 屏 | → 语音（屏缩为引用层） | 否（即时） |
| 耳机断开 | 语音 | → 屏 | 否（即时） |
| 麦克风分贝 > 阈值 | 屏 | 屏亮度降一档；**不切语音、不弹窗** | 否 |
| 用户长按主屏 3 秒 | 任意 | → 完全静默（手动 mute） | 否 |
| 进入新展厅 | 任意 | 仅更新 `Location` 状态，**不主动开口** | — |

#### 7.4.4 跨次记忆触发的三类规则

| 类别 | 触发条件 | 例（剧本对应） |
| --- | --- | --- |
| **风格脉络匹配** | 当前文物的 `style_lineage` ∈ 用户历史 | T5：北齐造像 → 国博曹衣出水 |
| **停留时长对照** | 用户在历史相似文物上停留 ≥ 3min | T14+30d：苏博 → 上博北魏立像 |
| **用户原话回引** | 用户曾使用的形容词命中当前文物特征 | T13 今日记忆卡引用「庄严」 |

三类必须命中其一才允许主动开口（§7.4.2 的 `Memory == warm`），且每次触发后该匹配进入 24 小时冷却。

#### 7.4.5 长程承诺（Promise Queue）

AI 说出"一会儿再聊"类陈述时，承诺会被记账：

```json
{
  "id": "promise_001",
  "made_at": "T4",
  "topic": "北魏 vs 北齐 衣纹对比",
  "fulfill_when": "Location == Hall:佛造像 AND CurrentArtifact.style == '北魏立像'",
  "expires_after_visit": true
}
```

满足 `fulfill_when` 时，**承诺兑现是 AI 主动开口的合法路径之一**（即 §7.4.2 之外的额外授权）——因为这是用户接受过的"约定"，不算反向打扰。

> 📌 这一节是 PRD → Figma → 工程之间的关键桥梁。Figma 阶段应基于此画状态流转图，工程阶段应基于此实现 reducer。

## 8. 形态决策

### 8.1 决策摘要

**屏为主，语音为辅。** 完整决策记录见 [ADR-001](./ADR/001-form-factor.md)。

### 8.2 克制式屏幕设计六条

选了「屏为主」后，最大的风险是滑回 Smartify / 三毛游的形态。以下六条反向约束让屏看起来**不像传统 App**：

| # | 约束 | 反例 |
| --- | --- | --- |
| 1 | 默认低亮 / 单点强光：进入展厅自动调暗，只在主动操作或 AI 主动开口时局部点亮卡片 | 全屏白底信息流 |
| 2 | 零滚动、零层级：任一屏一句话 + 至多一张图；展开靠切卡，不靠滚动 | 维基百科长文 |
| 3 | 零 push、零红点、零徽章、零连胜：App 不主动找你 | 任何打卡 App |
| 4 | 黑色为底、留白巨大：视觉重心永远是文物的图，不是 UI chrome | 一切政府网站风 |
| 5 | 「合上手机」按钮：每张卡都有把人推回实物的明确动作 | 没有任何对手做这件事 |
| 6 | 耳机即转语音：检测到耳机自动转单耳模式，屏切为最小引用层 | App 内播放器面板 |

### 8.3 语音作为旁路

语音不是替代屏，是**屏的影子能力**：

- 耳机插上时屏不消失，但缩成"引用层"（一行字 + 一张图）。
- 语音永远配字幕（无障碍 + 嘈杂环境备用）。
- 语音永远是单耳（社交礼貌 + 让用户能听见环境声）。

## 10. 内容与知识源

### 10.1 数据源分级

**一手**（最高优先级）：

- 上海博物馆开放数据 / 数字上博 API
- 其他主要馆方 API：故宫博物院、中国国家博物馆、Met Museum、V&A、Smithsonian Open Access

**二手**（学术）：

- CNKI、JSTOR、Artstor、Google Scholar 上的文物 / 艺术史论文
- 策展人手记、修复报告、拍卖图录（嘉德 / 苏富比 / 佳士得）
- 经选学术专著（如金维诺《中国佛教美术史》一类）

**显式禁用**：

- 百度百科、维基百科个别条目（除非有明确学术参考）
- 自媒体二创、营销软文
- 小红书 / 抖音文博 KOL 内容

### 10.2 RAG 架构（PM 视角简版）

```
用户问题 + 上下文（展厅 / 停留时长 / 用户历史）
    ↓
查询改写（LLM 把口语问题改成检索 query）
    ↓
向量检索（PG vector / Pinecone，命中 top-k 段落）
    ↓
重排（基于馆藏元数据 + 论文权威性打分）
    ↓
LLM 生成（system prompt = 人格 + 6 条话术 + 检索片段）
    ↓
长度约束 + 禁词检测
    ↓
输出
```

详细工程方案待技术 spec，PRD 阶段只需 PM 视角的"我知道这里有 RAG"。

### 10.3 反幻觉策略

- **不允许"复述记忆"超过 2 跳**：AI 不能拿着"它说它说"做事实陈述。
- **学界争议显式标注**：T9 那类场景必须给出来源。
- **馆方标签 vs AI 解读分层呈现**：T7 那个对照层。
- **不知道就说不知道**：T9 是优先表达，不是失败兜底。

## 11. 度量与成功标准

### 11.1 北极星指标

**每次参观中"用户主动发起对话的次数" / 参观时长（次/小时）。**

衡量"对等"是否真的发生：如果 AI 一直在播报、用户从不主动开口，这个值会接近零，说明关系仍是单向的。

目标值（v1 测试期）：> 4 次/小时（即平均每 15 分钟用户主动开口一次）。

### 11.2 反指标（防话痨、防把人拉回屏幕）

| 反指标 | 目标 |
| --- | --- |
| 单次 AI 发言平均长度 | ≤ 80 中文字 |
| 屏幕亮起时间占参观时长比 | ≤ 30% |
| AI 主动开口次数 / 用户主动开口次数 | ≤ 0.5（用户主动应至少是 AI 主动的 2 倍） |
| 单次参观会话总时长 | ≤ 实际参观时长（即不能"参观完仍在 App 内停留") |

### 11.3 定性评估

- 5–10 名真实用户的有声思考（think-aloud）参观；
- 离馆后 24 小时内的开放式访谈：「你今天还记得 AI 说过什么？」「你觉得它像一个什么样的人？」
- 长期留存观察：3 个月内的复用次数与跨馆使用次数。

## 12. 风险与边界

### 12.1 隐私

- 位置（蓝牙信标）、停留时长、说过的话、跨次记忆——都是高度个人化信息。
- 默认本地存储，云同步需明示开启。
- 跨次记忆数据可一键导出 + 一键清除。
- 不向馆方传输个人行为数据；如有合作，传聚合统计。

### 12.2 著作权与馆方关系

- 文物图像优先用馆方开放数据中的高清图。
- 学术论文采用"短引用 + 链接原文"，不全文存储。
- 不主张本产品是"上博官方"或任何馆方授权——明确独立第三方身份。

### 12.3 AI 立场 vs 学术权威性

- 「有立场」不等于「替代学术权威」——AI 的解读永远以「我倾向」开头，并永远附学界争议链接。
- 严肃错误（如断代张冠李戴）需要快速 hotfix 流程——v0 不展开，待 v1。

### 12.4 商业 / 持续性风险（含 napkin math）

本项目作为 side project 不假设商业回报，但作品集 reviewer 仍会问"如果做 3 年靠什么活下去"。两种假想路径的粗算：

**Path A · B2B 授权给馆方**

- 中国一级博物馆 ~30 家，二级 ~200 家。假设按定位（中高端）能覆盖一级馆 + 一线城市二级馆共 ~50 家。
- 单馆年授权费 30 万 RMB（参考 Smartify 在欧美的馆方授权费率），年营收 ~1500 万 RMB。
- 风险：馆方采购周期长（12–18 个月）、决策保守、且与馆方"权威讲者"心智冲突。

**Path B · C 端订阅**

- 国内文博中度爱好者粗估 50–100 万人（基于一级馆年访量与重访率推算）。
- 假设 5% 渗透 + 月费 30 RMB → ARR ~1500–3000 万 RMB。
- 风险：习惯门槛高（"博物馆是免费的"心智）；与微信公众号 / 小红书 KOL 内容竞争注意力。

**结论**：两条路都不是 SaaS 级飞速增长；本产品的商业上限**配不上 VC 投资逻辑**，更适合"小而美的独立产品 / 馆方合作 / 学术资助"组合的可持续路径。坚决不做的：广告、流量变现、KOL 联名——这三件事都直接违反产品灵魂。

### 12.5 真实使用场景的边界（v0 回避，v1 承认）

v0 PRD 默认用户独自参观、独自看每一件文物。评审团（用户代理 + 文博专家 + 战略 reviewer 三方）共同指出这是过度简化。v1 显式承认以下三类边界，并给出 v2 处理方向：

#### 12.5.1 同伴共看

**现实**：32 岁的文博中度爱好者中，**约 60% 的参观是与伴侣 / 朋友同行的**。两人共看同一件时，AI 应该说话吗？应该说给谁？跨次记忆是私有还是共享？

**v0 的回避**：§7.1 明确写"林独自来"。
**v1 的承认**：这是真实的市场约束——"独自看博物馆的产品"市场比作者预设的小。
**v2 处理方向**：(1) 单设备 + 共享耳机的"共听模式"；(2) AI 显式问"这件你想自己看还是和 ta 一起聊？"，由用户决定话语对象；(3) 跨次记忆仍为单账户私有，但允许在"共看"时段标记为 shared。

#### 12.5.2 信众语境

**现实**：佛教造像不只是艺术品。**约 5–10% 的参观者会在某些造像前合掌、礼拜、低声诵念**。AI 若延续艺术品评赏的姿态（"工匠的雕工""审美典型"），会构成对信仰的冒犯。

**v0 的回避**：完全没提。
**v1 的承认**：这是国内文博实际场景的真实伦理盲区。
**v2 处理方向**：(1) 设置/首启询问"你看佛造像主要是艺术兴趣 / 文化兴趣 / 信仰寄托" → 调节 AI 语气；(2) 检测到合掌姿态（手势识别）或佛教礼仪语音（"南无""礼敬"）时切换为低声 / 不评赏模式（与 §6.4.1 人格 prompt 中"信众语境"段落呼应）；(3) AI 默认不主动开口，等待用户主动询问。

#### 12.5.3 馆方博弈

**现实**：一个独立第三方 App 在馆内通过蓝牙信标识别用户位置、并在 T9 公开引述学界对馆方断代的不同观点——**馆方有合理理由要求停止**。Smartify 走"被馆方授权"路线，本质是回避了这层冲突。

**v0 的回避**：§12.2 一句话带过"独立第三方身份"。
**v1 的承认**：选择"独立第三方"的姿态本身是有战略代价的，不能假装没代价。
**v2 处理方向**：
- (a) **降级策略**：T9 类场景已在 v1 改为"先复述馆方判断、再补学界异见"，姿态从挑战变为补充；
- (b) **馆方友好路径**：未来若主动接洽馆方，提供"馆方观察后台"（聚合而非个人数据），让馆方看到用户在哪些件停留更久、哪些标签需要更新——把 AI 反过来变成馆方的研究助手；
- (c) **法律边界**：不在馆内通过红外 / 视觉做拍摄识别；蓝牙信标仅在用户主动授权后激活；不传输任何馆方未公开的元数据。

### 12.6 平台约束声明

PRD 中描述的若干交互在 v0 阶段未充分考虑平台 API 真实能力。v1 显式列出已知约束与妥协方案：

| v0 描述 | 平台真实约束 | v1 妥协方案 |
| --- | --- | --- |
| T2「锁屏上点亮小圆点，屏幕不亮起」 | iOS / Android 锁屏 API 不允许应用控制局部唤起 | 改为「抬手识别 + 锁屏 widget」组合（iOS 17+ / Android 14+ 原生支持） |
| T8「环境噪声 → 自动推送提示」 | 麦克风后台监听有隐私争议且耗电高 | 改为「只调亮度不弹窗」+ 麦克风采样仅在 App 前台时启用，且默认关闭，需用户主动开启 |
| T13 离馆模式自动触发 | 蓝牙信标"离开"事件不可靠，且不能在 App 完全杀掉时唤醒 | 退化为"用户离开 + 下次打开 App 时呈现今日记忆卡"，不强求实时 |
| 跨次记忆调用历史 | iCloud / Google Drive 同步有 quota 与延迟 | 元数据本地 SQLite + 周期性增量同步；不依赖实时云查询 |

完整平台能力 → 产品能力的映射应在 v2 的工程 spec 阶段补全。
