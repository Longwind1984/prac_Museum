## 总判定

**REDIRECT**(姿态创新真实,但兑现度不足 + 自身陷入新一轮"narrate 克制"的副作用)

v3 不是 v2 的进化版,是 v2 的对照实验。它押了三个相对正确的方向:**mode-shift("我说一句吗" + 等等 / 好)**、**静默配额可见(3 次)**、**5 chip 显式声明状态作为 ground truth**。这三处都对 v2 的"家长姿态"做出了真的姿态修正——v2 是"我说完锁你 60 秒消化",v3 是"我先问一下能不能说"。从礼貌学上,这是真的改进。

但 v3 同时落进了 **Innovator 自己在骨架里警告的同一个坑**:**用结构 narrate 克制**。

- 状态吊牌(status badge)写"我在听"——一个真听的人不会胸前挂个牌子说"我在听"
- "静默配额 3/3"显式可见——把 v2 的 throttle 家长姿态做成了**数字版的家长**(从锁时间变成发代币)
- `deriveAIState()` 函数 10 行就能看完,它**不是状态机**——它是"看当前 TP 的字段返回个字符串"的纯派生函数,没有迁移逻辑、没有事件入口、没有 transition table。"状态机"在 v3 里是**词,不是机制**

Innovator 骨架的 6 个引发条件 + 7 条不引发条件,**v3 落地的部分不到 30%**。骨架最辣的 negative-space("用户连续写笔记 > 30 秒任何 trigger 暂停"、"静默 > 25 分钟但用户在深看不 ping"、"用户 dismiss 2 次同类 trigger 当天封口")**一条都没有实现**。v3 把 Innovator 的"动态触发"翻译成了"在每张卡前面加一个 mode-shift 按钮"——这是 throttle 的姿态改造,**不是真正的动态触发**。

**结论**:v3 在"姿态"维度对 v2 有真进步(mode-shift 是好设计),但在"诚实度"和"Agent 设计模式真实性"上对 v2 是**退步**——把 v2 已经修干净的"数字诚实"问题(TOC 写"6 我开口 = 4 重 + 2 轻",但实际是 5 重 + 1 轻,且 anchor recall 不计入,真总数 7)又犯了一遍,且引入了**新一类自我标榜的 UI 装饰**(status badge / 配额数字)。

招聘官看 10 分钟:**第一眼**"哦 mode-shift / 静默配额——这版有 Agent 姿态思考";**第三眼**"状态机在哪——这 5 行 derive 函数不是状态机";**第五眼**"状态吊牌'我在听'……一个真听的产品需要挂这块牌子吗";**第十眼**"v2 的 8 + 4 数字 bug,v3 又一次 6 = 4 + 2 数得不对"。**会想聊,但聊的话题是"v2 和 v3 你自己更喜欢哪个,为什么"**——这反而是个好招聘信号。

## v3 自身新问题(动态触发产品特有失败模式)

### 新问题 A【严重】"状态机"是词,不是机制

- **具体在哪**:`deriveAIState()` 函数(728-738 行)
  ```
  function deriveAIState() {
    const tp = TPS[state.idx];
    if (tp.aiState) return tp.aiState;
    if (tp.requiresModeShift && !state.modeShiftAccepted[tp.id]) return 'waiting';
    if (tp.ai && (state.modeShiftAccepted[tp.id] || !tp.requiresModeShift)) return 'speaking';
    return 'listening';
  }
  ```
- **为什么是问题**:
  - **AI 招聘官层**:这不是 state machine。state machine 有 state + event + transition + side-effect。这里只有 derived state from current card——本质和 v2 没有任何区别(v2 也是 idx + 几个 boolean)。**v3 自封了"状态机驱动"标签但里面是个 if-else**——招聘官看一眼就识破。
  - **诚实度**:TOC sub 写"状态机驱动"。注释写"v3 · 动态触发 · 状态机驱动"。但代码层面,任何 reviewer 5 秒就能看穿这是包装话术。
  - **比 v2 退步**:v2 没自封状态机,只自封"3 处看得见的 mechanic",做到了。v3 自封更大但兑现更小——**这是产品 sense 上比 v2 更差的诚实度**。
- **建议修复**:**二选一**。
  - **(优先)** 砍掉"状态机驱动"标签,TOC sub 改成"11 触点 · 5 重开口前先问邀请 · 1 轻开口 · 1 anchor 回看"——诚实描述实际做的事
  - **(备选)** 真做状态机:加一个 `transitions: { from, to, event, guard }[]` 数组,事件包括 noteInput / dwellTimeout / explicitDeclare / silenceTimeout,至少落地 Innovator 骨架的 D(note 关键词)+ E(累计时长)这两条最简单的事件触发——动态触发就成立了

### 新问题 B【严重】静默配额扣减规则的姿态错位

- **具体在哪**:864-875 行,用户点 mode-shift"等等"时 `state.quietQuota -= 1`
- **为什么是问题**:
  - **姿态颠倒**:**用户拒绝 AI 开口 → AI 的配额被扣** —— 这是"用户行使否决权"换"AI 损失主动权"。逻辑上是对的(AI 被拒绝就少 surface 一次),但**心智模型上是用户被惩罚**——"你拒绝我我下次更少说话"听起来像家长式撒手("行,你不让我说我就不说了")。
  - **反 v2 没做到反**:v2 用"60s 锁"对用户家长。v3 用"你拒绝我我就少出现"对用户内疚操纵。**家长姿态从"管你"变成"我赌气"**。两者都是家长。
  - **配额视觉强化此感**:status sheet 写"今日还能主动 surface 的次数",**"主动"两个字是误导**——v3 里 AI **从不真正主动**,所有开口都需要用户点"好"才出现。也就是说 quota 衡量的不是"AI 主动次数"而是"用户允许的次数"——但 UI 把它显示成 AI 的资源,姿态颠倒。
  - 另一个细节:用户点"好"**不扣**配额(859 行 inline 注释明说"AI only ever speaks after user invite, so we DON'T consume quota on user accept")——这意味着配额唯一减少途径是用户点"等等"。**配额数字的功能等同于"用户拒绝计数器"**。把"用户拒绝次数"显示为"AI 主动余额"是话术倒置。
- **建议修复**:**二选一**。
  - **(优先)** 砍掉配额扣减,把配额改成"今日 AI 主动 surface 已用 X / Y"——纯统计,不威胁,不操纵
  - **(备选)** 反过来:用户点"好"扣配额(AI 真用了一次主动权),用户点"等等"不扣(AI 没真说出口,不消耗主动权)。这符合"主动"语义

### 新问题 C【严重】5 chip 显式状态在产品流程里完全闲置

- **具体在哪**:state.declaredState 在 `render()` 整个函数里**只在 renderSheet 里被读取**(791-795 行,只用于在 sheet 里显示"你显式声明在 X")。没有任何 TP 渲染逻辑依赖 declaredState。`deriveAIState()` 也不读 declaredState。
- **为什么是问题**:
  - **PM 层**:用户点 chip 没有任何反馈,产品不变化。这是 dead UI——比 v1 的语音按钮更隐蔽(语音按钮看起来能用其实没接,这个 chip 看起来在切换状态其实没影响)。
  - **Innovator 骨架**:骨架明确"**显式声明永远是 ground truth**,sensor 只是兜底"。v3 实现了"声明"的 UI 但产品根本没有 sensor 也没有需要 ground truth 的逻辑——**ground truth 是为谁服务的**?这是装饰用 UI 把"显式声明"做成了"政治表态"。
  - **诚实度**:status sheet 里写"你显式声明在玛雅厅。这是 ground truth,我相信你。"——但相信完了 AI 什么都不做。**这是"我听见了"的礼貌敷衍 + UI 演出**。
- **建议修复**:**至少做一件 declaredState 真影响的事**。比如:declaredState = 'sipan' 时,如果当前 TP 是 maya 系列卡,显示一个浮动 hint "你说在西潘了,要跳到西潘卡吗"。或者:declaredState 决定 quietQuota 的速率(在馆内每个厅各配 1 次,而非 3 次池子)。**或干脆删掉 state chip,承认动态触发没做到**

### 新问题 D【中】mode-shift 的"被邀请"礼貌实质上是均匀化 throttle

- **具体在哪**:5 张重开口卡(maya-jade / sipan-1987 / sipan-burial / synth-sharp / next-day)**每一张**都用 mode-shift。文案差异在 `modeShiftQuestion` 字段(我想说一句关于玉的 / 我想说西潘的发现年份 / 我想说同葬的人 / 最后一段我说一句吗 / 昨天的展我问一个问题吗)。
- **为什么是问题**:
  - **mode-shift 的精髓是稀有性**——朋友偶尔说"打断一下,我说个事"才珍贵。**每一卡都先问一遍 = 仪式化 = 失效**。
  - **姿态张力**:Innovator 评 v3 时的关键问题——"每次重开口都问'我说一句吗',是有礼貌,还是把朋友变成了'先打招呼的服务员'"。**答案是后者**。
  - **数据感受**:用户在 4 小时里会看到 5 次完全相同 UI pattern("等等"/"好" 按钮 + 金色虚线框)。第 1 次新鲜,第 2-3 次确认了 pattern,第 4-5 次成为 boilerplate。**好的稀有性应该是 1-2 次,不是 5 次**。
- **建议修复**:**砍到最多 2 张 mode-shift**——保留对最重的(sipan-burial 同葬)和元 moment(synth-sharp 最尖锐)。其余 3 张回归直接渲染。这样"被邀请"成为稀有姿态而非默认 pattern。

### 新问题 E【中】status badge "我在听"违反产品自己的反讲解员立场

- **具体在哪**:header 右上 status-badge,5 个状态文字常驻屏幕:我在听 / 我在等你 / 一会儿说 / 现在 / 不在
- **为什么是问题**:
  - **元矛盾**:一个真克制的产品不会在屏幕角落实时直播"我现在在做什么"。"我在听"这三个字本身就是 narrate 克制——和 v2 被 R2 批评的 `.ai-silence` 显式组件是同一种病。
  - **Innovator 自己警告过**:骨架最后元问题段——"是用'显式状态吊牌'让 AI 状态可见(避免误判 AI 故障),还是干脆让 AI 状态完全不可见(真正的 negative space)?**前者安全。后者更诚实。**"——**v3 选了前者,Innovator 已经预警这是不诚实的安全选择**。
  - **PM 层有合理性**:动态触发产品确实需要让用户读懂 AI 状态,否则被当 bug。所以 status badge 不能简单删——它是被动态触发的不可见性逼出来的产物。**问题不是 badge 存在,问题是 5 个状态 label 太多 + 文案太自述**。
- **建议修复**:**减状态文字到 2 个**——"·"(默认 / listening / waiting / soon 合一,就一个点不说话)和"现"(speaking 时短暂出现 + 自动收回)。"我在听"这种自述删掉——一个真听的产品用安静而非用文字证明自己在听。

### 新问题 F【中】数字 bug 的镜像复发:TOC 6 我开口 = 4 重 + 2 轻 数得不对

- **具体在哪**:TOC sub 写"11 触点 · 6 我开口(4 重 + 2 轻)· 0 RAG · 状态机驱动"。实数:requiresModeShift 的卡 = maya-jade / sipan-1987 / sipan-burial / synth-sharp / next-day = **5 重**;不需 mode-shift 但有 ai.body 的 = spirit-translation = **1 轻**;**5 + 1 = 6 没错,但 4 + 2 ≠ 5 + 1**。另外 recall 卡的 anchor recall 是 AI 第 7 处主动行为(quote 用户的 anchor 是 AI 在向用户说话),未被计入。

- **建议修复**:TOC sub 改成"11 触点 · 5 重开口(mode-shift)+ 1 轻开口 + 1 anchor 回看 · 0 RAG · 动态触发"——分母分子都说清,且砍"状态机驱动"假标签(见新问题 A)。

## v3 相比 v2 的"反副作用"真实性核对

R2 后 Innovator 提出 v2 有 5 条副作用,v3 应该是对它们的修复——逐条核对真反 vs 换皮反:

| Innovator 指出的 v2 副作用 | v3 试图的修复 | 真反 / 换皮反 / 没动 |
|---|---|---|
| **1. 节奏均匀化(一厅一开口)** | TPS 从 12 → 11,但 5 张重开口的 mode-shift 全部用同 pattern——节奏感**反而更均匀**(每次重开口都先问) | **换皮反**(从内容均匀变成 ritual 均匀) |
| **2. 显式 narrate 克制(`.ai-silence` / `chipKind: silent`)** | 砍掉 `.ai-silence` 和 chipKind:silent(真减),但新增 status badge "我在听" + 静默配额 + state chip + status sheet——**narrate 立场的载体从"我在沉默"换成"我在听 / 我在等你"** | **换皮反**(narrative 频道换了一个,克制依然在被 narrate) |
| **3. anchor 私密性变 KPI**(v2 set + echo + recall 三次) | 砍掉 echo-anchor,回到 set + recall 二态 | **真反**(R2 建议被接受) |
| **4. 测试用户作为受试者(throttle 锁 + autoPause 锁)** | throttle 砍 + autoPause 砍。但 mode-shift "等等"扣配额是新一类隐性家长 | **半真反**(显性锁砍了,隐性内疚操纵新增) |
| **5. 多模态默认隐藏的代价** | 维持 v2 选择(只 spirit 暴露 photo) | **没动** |

**净结论**:**5 条副作用,真反 1 条 + 半真反 1 条 + 换皮反 2 条 + 没动 1 条**。Innovator 提案的"反 v2 家长姿态"在 v3 里**完成了大约 40%**。
