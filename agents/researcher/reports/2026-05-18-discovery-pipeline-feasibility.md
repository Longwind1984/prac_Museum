# Research · Discovery Pipeline 可行性 Meta-Report · 2026-05-18

**召唤者**:Orchestrator(PM 项目级 pivot 后 de-risking)
**题目**:基于 3 件样本 bundle 实测,评估 Open Discovery Pipeline 在 30 件 × N 类源知识库上的可行度,**输出给 ADR-006 的工程笔记**(不写 ADR-006 本身)
**置信度**:**中**(单实测样本 = 3 件;沙箱环境对大陆馆方域名 + 主要大陆媒体 + archive.org 全部 403,实测数据有偏)
**调研工具**:WebSearch、WebFetch(403 占比 ≈ 70%)、Bash + curl(403 占比 ≈ 95% 大陆相关域名)、Read + Grep(本仓库现有 5 馆数据)
**3 件样本**:
1. 山博 · 北齐观音菩萨五尊像(1954 太原华塔村出土)—— `sample-bundles/shanxi-northern-qi-guanyin-pentad.md`
2. 上博东馆 · 北齐白石佛立像(响堂山系)—— `sample-bundles/shanghai-northern-qi-white-marble-buddha.md`
3. 震旦 · 玉神人兽像(红山文化,**故意挑的难件**)—— `sample-bundles/aurora-hongshan-jade-anthropomorphic-figure.md`

---

## TL;DR(3 条)

1. **Pipeline 跑完 5 类源,平均 2.2 / 5 类实际到手内容**(Sample 1: 2/5;Sample 2: 3/5;Sample 3: 1.5/5)。**剩下的 3 类几乎全部因为"沙箱不可达大陆域名"卡住**——不是 pipeline 设计错,是**执行环境拿不到**;同一个 pipeline 在 PM 国内 IP / VPN / VPS 中转下**应该能拿到接近 4/5**(未实测,基于经验)。**这意味着 ADR-006 的 P0 决策不是『agent 怎么写』,而是『执行环境怎么定』**。

2. **5 类源在自动化可行度上呈极强分层**:
   - **来源 B(跨馆海外 OA 对照)= 高 / 100% agent 化** —— 本仓库已落地 466k 行 JSON,纯本地 grep
   - **来源 E(数字人文 / 跨域 OA)= 中-高 / 80% agent** —— BMFEA、MDPI、芝大项目网页可抓
   - **来源 C(学术论文)= 中 / 60% agent** —— URL 发现 100% agent;PDF 下载 + 解析需 PM 国内 IP 或绕路
   - **来源 D(现场场域 / 媒体长文)= 低-中 / 40% agent** —— URL 发现可,**内容必须人在回路**(微信 ToS / 大陆 IP 必备)
   - **来源 A(馆方一手页面)= 低 / 20% agent** —— **大陆馆方 100% 必须 PM 国内 IP**;海外馆已被现有 5 个 extractor 覆盖,无新工作

3. **30 件 bundle 的诚实工时估算 = 80–120 小时 ≈ 2.5–4 周 (单人 full-time)** —— 这是**人在回路成本占大头**的估算,不是 agent 推理时间。**若 PM 在国内 IP 环境每天能给 1–2 小时手动收材料,实际进度 = 6–8 周**。**绝不要承诺『agent 一周搞定 30 件』**。

## 1. 5 类源的自动化可行度评级(给 ADR-006)

> 评级标准:**「高」= 完全 agent 化,无人在回路;「中-高」= agent 跑通主路径,1 步人在回路(典型:T3 注册 / 申请 API key);「中」= agent 部分跑通,1–2 步明确人在回路(典型:大陆 IP 下载);「低-中」= agent 只跑 URL 发现,内容必须人在回路;「低」= agent 几乎不可介入**

### 来源 A · 馆方一手页面 → **低(大陆馆) / 中-高(海外 OA 馆,已落地)**

- **大陆馆方页面**(山博、上博、震旦、故宫、国博等):
  - 沙箱 100% 不可达(本次 3 件实测,3/3 馆方 URL 全 403)
  - **必须 PM 国内 IP 执行**;agent 只能负责"写爬虫脚本 + 列 URL 模式 + 写 robots.txt 合规检查器"
  - URL 模式可枚举性:**山博顺序 ID(`/sx/collection/detail/id/{N}`)友好**;**上博 V/I/RI 前缀 + 8 位 ID 必须先从检索页解析**;**震旦无系统 ID**
- **海外 OA 馆**:已被现有 5 个 extractor (cma/met/fsg/va/dunhuang) 覆盖,**本次样本完全不需要重写**
- **关键工程笔记**:
  - ADR-006 应明确:**A 类源对大陆馆 = 半人在回路;Pipeline 的 agent 输出 = 爬虫脚本 + URL 列表 + 字段映射 schema 草案,不是 metadata 本身**
  - 不要假设 wayback / Google cache 能绕路:**本沙箱 archive.org 完全不可达**

### 来源 B · 跨馆对照件(海外 OA)→ **高(100% agent)**

- **本仓库现有数据**:`cma.json`(86k 行)+ `met.json`(366k)+ `smithsonian_fsg.json`(75k)+ `va.json` + `dunhuang_open.json` + `tianlongshan_uchicago.json`
- **3 件样本中本类源命中量**:
  - Sample 1(北齐五尊像):28 件北齐造像直接命中(CMA 6 / Met 7 / FSG 14 / V&A 1)
  - Sample 2(北齐白石立像):同窗口,V&A O129249 provenance 直标 Xiangtangshan = **wow moment 工程基石**
  - Sample 3(红山玉神人):**0 件直接命中** = **现有数据池在新石器窗口结构性空白**
- **关键工程笔记**:
  - **这是 pipeline 中唯一可全 agent 化且零外部依赖的一环**
  - ADR-006 应把"B 类源"标为**pipeline 默认起点**:任何件先 grep B,看命中数,再决定后续投入
  - Track 2 已建议接入 AIC + Harvard + Penn + Cernuschi(4 个新馆),做完后 B 类源覆盖度还会再上一层
  - **B 类源失败的件(如 Sample 3)= 早期警示信号**:这件 demo 的 wow moment 必须靠 C / D / E 撑起,如果撑不起,**应该从 30 件清单里劝退**

### 来源 C · 学术论文 / 学者文章 → **中 / 60% agent**

- **agent 可自动化部分(URL 发现)**:
  - `site:dpm.org.cn filetype:pdf 北齐` 等 Google CSE / DDG query
  - 学者个人站点(echildsjohnson.wordpress.com 等)定向爬
  - MDPI / DOAJ / BMFEA / archive.org Met OA 全文 PDF 索引
  - 山西大学云冈学知识库 `ygx.sxu.edu.cn`(Track 3 §B4 已识别)
- **人在回路部分**:
  - **dpm.org.cn / kaogu.cssn.cn / archive.org 在本沙箱 403** —— 国内 IP 或 VPS 中转
  - PDF 文本提取(`pdftotext`)是 agent;但**前提是 PDF 已落本地**
- **3 件样本中的差异**:Sample 2(白石佛 + 曲阳)学术覆盖**最密**(5 个独立学术源直接命中);Sample 1 中等;Sample 3 学术深度反而**比馆方深** —— 这是反直觉发现,**应该让 ADR-006 接受「某些件学术源 > 馆方源」**
- **关键工程笔记**:
  - ADR-006 应分两层:**C1 学术 URL 发现 = agent**;**C2 学术 PDF 下载 + 解析 = 半人在回路**
  - 不要把 dpm.org.cn 当成不可绕过的依赖:**Track 3 §B5 BMFEA 全卷 OA 是真正可机器抓的金矿,且 CC-BY 允许 RAG 全文向量化** —— 这点应在 ADR-006 P0 写明

### 来源 D · 现场场域 → **低-中 / 40% agent**

- **agent 可做**:URL 发现 + 馆方公众号文章标题清单 + 媒体长文索引
- **agent 不可做(硬边界)**:
  - 微信公众号 RSS 是 ToS 灰区 + 平台持续封杀(Track 1 §C8)→ **绝对不抓**
  - 三毛游 / izi.TRAVEL 商业付费内容 → 不抓
  - 大陆媒体长文(澎湃 / 知乎 / 新浪)→ 国内 IP 才能稳访问
- **3 件样本中本类源到手率**:**0/3 实际内容**到手;**3/3 URL 清单**到手
- **关键工程笔记**:
  - ADR-006 把"D 类源"定义为 **「agent 找位置,人工收材料」** —— Track 1 §B.3 已写,本次实测 100% 复现
  - 不要承诺"AI 找全网新闻报道并入库" —— 这是 PRD 不能签的承诺

### 来源 E · 数字人文 / 跨域 OA → **中-高 / 80% agent**

- **agent 可做**:芝大天龙山 / 响堂山项目网页文字爬取(本机沙箱 403,但 PM 国内 IP 可达;Track 2 §B6 已建议)、MDPI / OCS 学者讲座 OA 抓取、CBETA 第三方 API、Wikidata Q-ID 反查
- **人在回路**:数字敦煌实名注册(T3)、3D 高精数据邮件申请(T3)
- **3 件样本中差异**:
  - Sample 2 命中**最密**(响堂山项目 + 国博临展专题页 + 数字敦煌 + CBETA + dunhuang_open.json,5 个独立源)
  - Sample 3 命中**最稀**(新石器件几乎无跨域佛教/敦煌联系)
- **关键工程笔记**:**E 类源是 Pipeline 给"反幻觉编排状态机"提供 chunk 的核心来源**,应在 ADR-006 P0 列为优先级第二高的源(仅次于 B)

## 2. ADR-006 应该把哪些步骤定义为 agent / 哪些定义为人在回路

> 不写 ADR-006,只供工程笔记。

### 完全 agent 化(P0 自动跑)
1. 跨馆对照 grep(`data/sources/*.json` 本地查询)
2. WebSearch / site: 限定的 URL 发现
3. 学术 OA(MDPI / DOAJ / BMFEA / Smarthistory)PDF 下载 + 七字段解析
4. Wikidata Q-ID 反查(Track 2 已建议)
5. 跨馆 accession 索引(响堂山 / 天龙山公开页 + 现有海外馆 OA 数据交叉,Sample 2 已实质交付雏形)
6. 海外 OA 馆 metadata 抓取(已 5 个 extractor,新增 AIC / Harvard / Penn 同模式)

### 半 agent 化(agent 起草,人审批)
7. 大陆馆方爬虫脚本(agent 写,**PM 国内 IP 执行**)
8. 学术 PDF 下载策略(agent 列 URL 清单,**PM 国内 IP 执行 dpm.org.cn 等域名**)
9. license 分层判定(agent 抓 → 人 review → 入 schema enum)

### 必须人在回路(agent 不能做)
10. 馆方说明牌实地拍摄 + OCR review(F-16 已规划)
11. 微信公众号订阅 + 文章人工摘抄
12. 大陆媒体长文阅读 + 引用入库
13. 馆方非公开素材沟通(T3,如天龙山 3D 邮件申请、数字敦煌实名)
14. 私立馆方法论叙事(震旦"古器物学四维")—— **只能现场拍 + 手动摘**
15. 真伪争议 / 权力结构 chunk 的最终人格化措辞(原则 C 落地)

## 3. 30 件 bundle 的预估时间成本

### 单件 bundle 工时(基于本次 3 件实测外推)

| 阶段 | Sample 1(山博,中等) | Sample 2(上博,密) | Sample 3(震旦,稀) | 平均 / 件 |
|---|---|---|---|---|
| 0. 展品识别(选品 + 关键词) | 0.5h | 0.5h | 1h | 0.7h |
| 1. 来源 A(馆方一手)—— **沙箱 0,假设 PM 国内 IP 1.5h** | 1.5h | 1.5h | 1.5h | 1.5h |
| 2. 来源 B(跨馆对照)—— 本地 grep + 论证 | 0.5h | 0.5h | 0.3h(空) | 0.4h |
| 3. 来源 C(学术) | 1h | 1.5h | 1h | 1.2h |
| 4. 来源 D(现场)—— PM 国内 IP 抓 + 摘 | 1.5h | 1.5h | 1h | 1.3h |
| 5. 来源 E(跨域 OA) | 1h | 1.5h | 0.5h | 1.0h |
| 6. 评估 + 7. 反向 + 写 bundle | 1h | 1h | 1h | 1.0h |
| **单件合计** | **7h** | **8h** | **6.3h** | **~7h** |

> **本次样本实测**:Researcher 单件实际工时(不含 PM 国内 IP 那部分,即不算 A/C/D 的"PM 执行"工时,因为本沙箱跑不了)≈ 1.5–2h。**意味着 PM 国内 IP 段大约占 50–60% 总工时**。

### 30 件总工时 = 30 × 7 = **210 小时**,但有以下减折:

- **复用红利**:30 件中应有 10–15 件是"同窗口同类目"(如北朝—初唐 8–12 件),其学术源 + E 源大量复用 —— 减 **~30%** 工时 → **150 小时**
- **agent 化深做后**:60% agent 占比可以再压 —— 减 **~25%** → **110–115 小时**
- **PM 国内 IP 段**:大约 **30–40 小时**(平均每件 1–1.3h)是 PM 自己的实际工时,**不能 agent 化**

### 诚实标"如果按这个速度,30 件需要 X 周"

- **PM full-time 投入(40h/周)+ Researcher agent 全力**:**3 周左右**完成
- **PM 兼职(每天 1.5h 国内 IP 段)+ Researcher agent 跑剩余 70%**:**6–8 周** —— **这是建议作为基线的现实估算**
- **若大陆 IP 段被严重卡(网络问题、馆方反爬、PM 国内时间稀缺)**:**10–12 周**

### 给 PM 的硬数字(不要灌水):

> **30 件 sample bundle ≠ 30 件 demo-ready bundle**。本次 3 件实测后,**Researcher 的诚实判断是**:
> - **6 周内**:可拿到 25 件 metadata + 18 件较完整 bundle + 8 件 wow moment 工程化雏形
> - **若要 30 件全部达到 Sample 2 的完整度**(B + C + E 都密)**,需要 ≥ 10 周** —— 而且**前提是 30 件清单本身就经过 B 类源筛过**(即先确认每件至少有 5+ 件跨馆对照才入清单,Sample 3 这种类型应被劝退)

## 4. 必须升级到 PM 的 5 件事

1. **执行环境 = ADR-006 真正的 P0 决策**:本沙箱环境对大陆所有馆方 + 大陆媒体 + archive.org 100% 不可达。Pipeline 写得多漂亮,**没有国内 IP / VPS 中转 / PM 手动执行其中之一**就跑不完整链路。**PM 必须先决定:(a) 是否申请国内 VPS?(b) 是否 PM 个人每周固定时段在国内执行人在回路?(c) 是否找 PM 国内朋友承担一部分?** —— **不解决这一点,30 件全是空谈**

2. **数字敦煌实名注册 / 天龙山 + 响堂山 3D 邮件申请**:这两条 T3 边界事项 ADR-003 已留位;**Sample 1 + Sample 2 都受影响**;ADR-006 应该明确"Phase 1 不申请(只用公开网页),Phase 2 决定" —— 是否就这条政策正式 sign-off?

3. **新石器 / 高古玉 / 良渚 / 红山等窗口在海外 CC0 馆覆盖度极差**(Sample 3 实测 0 件直接命中)。**PM 决定:30 件清单是否承诺"全部有强海外对照件"?如承诺,则新石器件应从清单中删除;如不承诺,则允许 Sample 3 这种"靠学术 + 真伪争议撑场"的件,**但要在 PRD 中诚实标"部分件无跨馆对照,以学术叙事为主"**

4. **大陆馆方策展声明在公开渠道几乎不存在**(Sample 1 印证 Track 3 §D1):山博 / 震旦 0 条馆方一手 PDF。**PM 决定:是否接受"AI 同伴的策展声明叙事大量基于二手报道反推"作为 Phase 1 限度?并在产品中诚实标"馆方未公开,以下基于第三方报道"**(原则 C 落地,本身可成为产品哲学卖点)

5. **微信公众号是大陆现场场域的核心载体,但 ToS + 反爬使 100% 程序化不可行**。**PM 决定:是否接受"D 类源 = 用户手动收集,产品不承诺自动抓取"作为 PRD §1.4 USP 的诚实边界?**

## 5. 建议 ADR-006 在产品 PRD §1.4 USP 里写一句什么

(给 Builder 起草用,**Researcher 不下产品决策**,以下仅供参考措辞)

候选 A(强调"市面唯一"):
> "我们用 AI agent 从分散的、版权不一、可达性不一的中文文博源中,为每件展品拼出一个跨馆对照 + 学术对照 + 现场场域三维度的 bundle。**这种知识库市面上不存在**——馆方各自只展示自己的件;聚合站(中华珍宝馆等)版权状态不明且字段薄;学术论文池散落在 dpm.org.cn / BMFEA / academia.edu / 山大云冈学。**我们做的是把它们拉到一起的那个 agent**"

候选 B(强调"诚实标边界"):
> "30 件展品 × 5 类源 = 150 个 bundle 单元。**Pipeline 实测中,平均每件能稳定到手 2–3 类源;部分件(私立馆 / 新石器窗口)只能到手 1 类**。我们不承诺『AI 替你搞定一切',我们承诺『AI 告诉你能拼到什么 + 拼不到什么 + 为什么拼不到 ── 后者本身就是中国文博数字化现状的产品哲学』"

候选 C(强调"原则 C 落地"):
> "**找不到一手叙事本身就是产品哲学素材** ── user-voice 原则 C。Pipeline 实测:震旦『玉神人兽像』馆方说红山,但海外学者明示该类件『从未经科学发掘出土』。馆方说明牌不会写这一句。AI 会"

**Researcher 倾向**:候选 B + C 的合并 —— 既诚实标边界,又把边界本身变成产品哲学。

## 不确定 / 需要进一步调研

1. **沙箱外可达性差**:dpm.org.cn / kaogu.cssn.cn / 各馆官网 / archive.org / wayback 全部本机 403;以上工时估算建立在"PM 国内 IP 段都能成功"假设上,**未实测**。建议 PM 用国内手机网络对 5–6 个关键 URL 各试一次,确认实际可达性后再调工时
2. **微信公众号订阅频率与文章覆盖度**:Track 3 没具体测每个馆公众号月发文密度;PM 实际订阅后才能定 D 类源 chunk 量级
3. **CBETA 第三方 API 稳定性 / Cernuschi 数据接入工程量** —— Track 2/3 已留 P1,**未由本次样本验证**
4. **30 件清单的真实跨馆对照命中率分布**:本次 3 件中 1 件密(Sample 2)、1 件中(Sample 1)、1 件稀(Sample 3)。**30 件抽样比例可能不同**,Curator 需要重选 exhibit-list 后再校准
5. **PM 国内 IP 段每周可投入时间**:**未与 PM 对齐**;直接影响 6-8 周还是 10-12 周

## 给召唤者的具体建议

1. **ADR-006 的核心问题不是『agent 怎么写』,是『执行环境怎么定』** —— 先解决 5 件升级事项中的第 1 件,再写 ADR-006
2. **不要承诺 30 件等深** —— 接受 Sample 1/2/3 的差异,产品哲学化"诚实标完整度"
3. **B 类源是 wow moment 的工程基石** —— Sample 2(响堂山系)已实质交付雏形,**应该作为 ADR-006 P0 落地的第一个具体例子**
4. **Sample 3 类型的件(私立馆 + 冷窗口 + 真伪争议)是 user-voice 原则 C 的最强产品落地** —— 不应该从清单删,但应该单独标"叙事 wow > 数据 wow"
