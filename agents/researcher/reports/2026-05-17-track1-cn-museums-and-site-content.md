## TL;DR(给 Curator 的 3 条)

1. **大陆馆方数据缺口的真实形态 ≈「有展示 ・ 无接入」**——7 馆全部都有面向 C 端的"在线藏品检索/数字展厅/小程序",但**没有一家提供官方 API / 批量下载 / CC0 协议**。数据存在,但是以**人对屏**形态投放,不是**机对机**形态。这与 ADR-003 已有判断"大陆没有任何一家馆达到 Met / V&A / Smithsonian 的开放水平"完全一致——本次调研**没有发现需要推翻 ADR-003 的新事实**,只是把"开放度低"细化为"展示型 vs 接入型"的具体差异。

2. **本周可实操接入的 2-3 个源**,按相关性 + 难度排:
   - **a. 山西博物院官网 `shanximuseum.com` 定向爬虫**(P0):URL 结构可枚举(`/sx/collection/detail/id/{N}`),用于补 30 件展品 metadata anchor。**唯一能真正堵住 backlog #4 大陆馆方 0 条**的源。
   - **b. 上博官网 `shanghaimuseum.net/mu/frontend/pg/collection/antique` 关键词检索**(P0):上博东馆中国古代雕塑馆 289 件公开展品中约 1/3 首次公开,北朝—初唐切片极契合。同样无 API,但可走"页面参数化关键词"路径。
   - **c. 故宫院刊 PDF 直链 + dpm.org.cn 数字文物库 metadata-only 摘取**(P1):ADR-003 已选定,本调研确认仍是最干净的"学界半 OA"源——尤其北齐徐显秀墓相关论文已直链可用。

3. **三个"看似可用其实不行"的反向发现,Curator 应立即避坑**:
   - **「中国文物云」/ 国家文物局 180TB 数据库** = 是行政管理后台,**不对公众/开发者开放**。"数据汇聚 ≠ 数据开放"——这个差异在中央层面尤其大。
   - **数字敦煌开放素材库** "免费"是**个人欣赏/研究免费下载,商用 300–800 元/张** — 上一轮 Curator 已盘点过,本调研再次确认(2026-05-17 价格未变)。Side project 本身定位是"非商用 demo",但若放进作品集走向招聘面试可能落入灰区,**默认不入库,改为外链跳转**。
   - **「天龙山 UChicago tls.uchicago.edu」3D 模型** — 站点在本环境直接 403。3D 数据需邮件申请,但**联系外部人触发宪法 T3**;在 PM 决策前**不能由 Researcher 主动发邮件**。这意味着 ADR-003 主源 D 在 Phase 1 实际**只能用站内 2D 展示页 + 链接外引**,不能本地化。

## A · 大陆 7 馆逐馆评估

> 所有"国内访问性"基于一个事实前提:**本调研环境(美国 IP)对所有大陆馆方域名 + chwhyun.cn 一律返回 HTTP 403**(curl HEAD 实测 2026-05-17)。这意味着:(a) 任何 demo 的爬虫必须在国内或经代理执行;(b) 反过来,**站内服务对国内用户应是可达的**——这是产品在国内现场场景的基本前提。

### A.1 山西博物院(山博) — **核心 anchor 馆**

| 维度 | 内容 |
|---|---|

| 接入难度(1-5) | **2**(爬虫定向抓取 30 件 anchor 件) ~ **3**(整馆系统化抓取)。无 robots.txt / 反爬强度证据,假设为常规反爬。**URL 结构 `/sx/collection/detail/id/{N}` 可枚举是关键利好**——只要 ID 不是稀疏散布,二分探测即可定边界。 |

| 推荐优先级 | **高 P0** |

### A.7 龙门石窟研究院 / 云冈研究院(任选其一)

> 二选一的逻辑:demo 切片是「天龙山 × 山博」,而**天龙山在地理上属山西,北朝石窟艺术上属"云冈→天龙山→龙门"一线**。云冈(大同)地缘上更近山博 + 天龙山,但 demo 切片中的"风格脉络对照"实际上**云冈 + 龙门都要用**——这不是"任选其一",而是"两座都要,但只作链接外引,不要落本地"。

| 维度 | 龙门 | 云冈 |
|---|---|---|
| 官方 API | 无 | 无 |
| 数字平台 | **「云上龙门」微信小程序**(2021 上线) + 浙大龙门研究院联合实验室 + 数字孪生平台 | **「数字云冈」先进计算中心**(2.3PB 数据,234 万亿次/秒算力,内部) + 微信小程序"云冈云" + 5G 双域专网 |
| 公开高清数据 | **未公开**(2025 起 80% 洞窟数字化,但成果在小程序展示) | **未公开**(80% 洞窟数字化,数据在内部计算中心) |
| 学术合作可达性 | 浙大 + 北大有合作通道(走馆方/学术机构,非个人) | 与多家高校合作,但 side project 个人无路径 |
| 图像许可 | 无 CC0 | 无 CC0 |
| 国内访问性 | 主入口:微信小程序"云上龙门"+ 公众号「龙门石窟世界文化遗产园区」 | 公众号「云冈研究院」+ 小程序"云冈云" |
| 接入难度(1-5) | **5**(小程序内容无 Web 端,无法系统抓取) | **5**(同上) |
| 推荐优先级 | **不推荐数据接入** / **推荐叙事引用 P1** |
| 关键链接 | 小程序:微信内搜"云上龙门" / "云冈云";官方报道见 2025 光明日报 / 国家数据局案例集 |
| 备注 | **本次调研最强反向发现之一**:云冈 + 龙门虽然技术化程度最高(PB 级数据 + 三维扫描精度毫米级),但**对 C 端开发者完全封闭**——所有数字化成果都包装为"小程序展示 + 内部计算中心",不释出底层数据。这把 ADR-003 附录二的"主题层"判断再次坐实:**单一石窟数字化项目不可作为数据底座,只能作为现场触发点与外链**。 |

**结论**:龙门 / 云冈 **不作为数据源**,只在 RAG chunks 中以"链接 + 短摘"形式出现(类似 ADR-003 对天龙山的处理)。

## B · 现场场域 5 类源

### B.1 展览说明牌(wall text)数字化数据集

| 维度 | 内容 |
|---|---|
| 现成 OCR 数据集 | **未发现专门的"博物馆展板 OCR 数据集"**。中文场景 OCR(CTW、RCTW-17)针对街景文字,不针对展厅低光照 + 玻璃反光场景。 |
| 学术研究项目 | 数字人文领域有"图像资源语义化建设"路线(见 [中国数字人文](https://www.dhcn.cn/dhjournal/202002/2615.html)),但**未见任何"系统化扫描某馆全部说明牌并发布数据集"的公开项目**。 |
| 替代路径 | (a) PM 自己/朋友实地拍摄上传 + LLM-OCR(ADR-005 F-16 已覆盖此机制);(b) 馆方公众号长文常隐含说明牌内容(见 B.3);(c) 三毛游 / izi.TRAVEL 的讲解词常**精确改写自说明牌**,可作间接源。 |
| 接入难度(1-5) | **4**(无现成数据,需自建管道) |
| 推荐优先级 | **中 P1**——本调研**无法绕开"必须实地拍"这一步**;PRD F-16 / ADR-005 Tier 1 已规划。 |
| 关键发现 | **没有公开的中国博物馆展板 OCR 数据集是 Track 1 的最重要负向发现之一**——任何号称"已有"的数据集都需直接验证,大概率不存在。 |

### B.2 官方 audio guide 文本

| 维度 | 内容 |
|---|---|
| 三毛游 | **覆盖 100+ 国家 / 15,000+ 景区博物馆**,含山博 + 上博 + 国博 + 故宫等核心馆。**支持离线下载**(登录后)。但**讲解词文本无官方导出口径**——只能听音频。 |
| izi.TRAVEL | **有公开 API**(`izi.travel/en/izi-api`),全球 1,750 馆 / 10,100 audio tours 覆盖。**API 可调出文本 + 音频文件**(开发者文档明示)。**但中国大陆馆覆盖度弱**——上博 / 山博是否有官方频道未确认,大概率为 UGC 而非馆方供稿。 |
| 馆方 App | 上博 App / 国博 App / 故宫 App 各自内置导览音频,**无文本导出口径**。 |
| 官方有声讲解器 | 物理设备(展厅租借),文本完全闭源。 |
| 接入难度(1-5) | **三毛游:4**(无 API,音频→文本需 STT) / **izi.TRAVEL:2**(有 API,但中国覆盖弱) |
| 推荐优先级 | **中 P1**——izi.TRAVEL API 试探一次(免费),如果上博 / 山博有官方频道则是金矿;若没有则放弃,改走三毛游音频 + STT(但**这有版权灰区**:三毛游讲解词是付费内容,音频转文本入 RAG 不合规,**建议放弃**)。 |
| 关键链接 | `https://izi.travel/en/izi-api` ; `https://sanmaoyou.com/` |
| 关键发现 | **三毛游讲解词不可作为 RAG 源**——这是商业付费内容,即使能技术抓取也踩版权与平台 ToS 红线。izi.TRAVEL API 是唯一合规候选,但需先验证中国馆覆盖度。 |

### B.2.5 PM 自摄音频 / 馆方有声讲解器抓取

| 维度 | 内容 |
|---|---|
| 物理设备 | 山博 + 上博 + 故宫 + 国博的现场有声讲解器(物理租借)文本闭源,**音频可在现场录音 → STT 转写**——但这是用户级行为,**不可作为产品 RAG 源**(版权)。 |
| 用户自录上传 | ADR-005 F-16 用户众包路径可以接受"用户拍下展板自动入库",但**禁止任何'协助标注'按钮**——这条原则对音频同样适用:不能引导用户录音上传讲解器音频。 |
| 推荐优先级 | **不推荐** |
| 关键发现 | 这条路径主要风险在产品上线后被舆论问责"诱导用户侵犯讲解器版权",PRD §12.2 已有合规约束。本调研只是再次确认这条边界。 |

### B.3 馆方公众号长文

| 维度 | 内容 |
|---|---|
| 价值定位 | **大陆馆方非正式叙事的主战场**——展品深度解读、策展声明、策展人专栏、临展导览大多首发于公众号。山博、上博、故宫、国博、龙门、云冈、青州都有活跃官方公众号(已交叉验证)。 |
| 归档项目 | **无任何系统化的"博物馆公众号归档"公共数据集**。现有开源工具:WeChat-Feeds(6200+ 号已覆盖,**已停止服务**)、wechat-download-api(2025 活跃)、we-mp-rss、WeRss、WeChatRSS、wewe-rss 等。所有方案靠**间接抓取**,**被微信持续封杀**——"目前公众号 RSS 方案基本被平台封杀的差不多了"(2025 报道)。 |
| 自建可行性 | (a) 通过 `mp.weixin.qq.com` 历史文章接口(需 Cookie,可批量) — 技术可行但易封号;(b) 通过第三方 RSS 服务订阅 — 稳定性不可控;(c) 通过搜狗微信搜索 — 已 2023 停止索引近期文章。 |
| 接入难度(1-5) | **4**(技术不难,合规与稳定性差) |
| 推荐优先级 | **中 P1**——但**强烈建议不要做"全量抓取"**,改为「定向追踪」:订阅 10 个核心馆 + 关键期(临展开幕/重要节假日),手工 + 半自动方式累积。 |
| 关键发现 | 微信公众号**没有合规、稳定、可规模化的程序化访问方式**——这是中文文博 AI 产品的结构性短板。任何 demo 把"公众号长文 RAG"作为核心承诺都会在第一次大规模上线时翻车。 |

### B.4 馆方图录(出版物)

| 维度 | 内容 |
|---|---|
| 数字化情况 | 山博 + 上博 + 国博的核心图录绝大多数**未数字化对外**。部分通过文物出版社、上海书画出版社发售实体书;**第三方扫描共享(超星 / 知网图书馆 / 书格)有零散但不系统**。 |
| 学者扫描共享 | 书格(`shuge.org`)有故宫 / 上博的早期图录扫描件,**但版权灰区**——不可入库,只可阅读参考。 |
| 知网 / 超星 | 知网有部分馆方期刊全文(《文物季刊》《故宫博物院院刊》《考古》《文物》等)——见 ADR-003 L2 通用层(已落地,**走"短引用 + 反向链接",不全文向量化**)。 |
| 接入难度(1-5) | **5**(实体书数字化是巨工程;学者扫描件版权灰) |
| 推荐优先级 | **不推荐**——已被 ADR-003 排除在数据底座之外。 |
| 关键发现 | **图录数字化在中国大陆是 5–10 年级的"未解决"问题**。Side project 不应触碰。 |

### B.5 馆方布展声明 / 策展人文章

| 维度 | 内容 |
|---|---|
| 主要载体 | (a) 馆方公众号(见 B.3);(b) 馆方网站"展览"栏目说明文字;(c) 策展人在外刊发文(故宫院刊 / 文物 / 美术 / 收藏家等)。 |

## 给 Orchestrator 的具体建议

### 立刻接入(本周)

1. **山博官网定向爬虫**(`shanximuseum.com/sx/collection/detail/id/{N}`)——枚举 ID 范围 + 关键词过滤(佛 / 造像 / 北魏 / 北齐 / 北周 / 隋 / 唐),目标 30–50 件 anchor 件 metadata。**这是 backlog #4 唯一能堵住"大陆馆方 0 条"洞的源**。Effort: 1–2 天 single-dev,需国内 IP 或代理。
2. **上博官网关键词参数化抓取**(`shanghaimuseum.net/mu/frontend/pg/collection/antique?keywords=…`)——按"佛 / 造像 / 北朝 / 北齐 / 北魏 / 隋 / 唐 / 雕塑"等关键词列表抓取,目标 100 件以内对照件 metadata。Effort: 1 天,同需国内 IP。

### 放弃 / 暂停

7. **不要做"全量大陆馆方公众号归档"**——平台对抗 + 合规风险 + 维护成本 → 性价比反原则。
8. **不要做"展板 OCR 数据集自建"**——没有现成可用的,ADR-005 F-16 Tier 1 已规划用户拍照众包,等 Phase 2。
9. **不要追龙门 / 云冈的底层数据**——只作"现场触发点 + 外链",同 ADR-003 对天龙山的处理。
10. **不要爬"中华珍宝馆"等第三方聚合站**——版权状态不明,且其图源还是各馆官方,绕一圈无新价值。

### 需要 PM 决策的灰区(T3 escalation)

11. **是否联系芝大天龙山项目申请 3D 高精数据访问授权?** — ADR-003 已标"邮件申请明示授权";本调研 reconfirm 此动作触发 T3,需 PM 决策。**建议优先级在 Phase 2**,Phase 1 demo 用站内 2D + 链接外引足够。
12. **是否联系数字敦煌就 demo 中**非商用**使用 + 招聘面试展示 sign-off?** — 同 T3。**Researcher 建议: Phase 1 default 不做; 改为外链 + 缩略图; 若 PM 决定要 demo 中铺敦煌纹样底图,再起 T3。**
13. **是否在 PM 的山西本地朋友处获取山博馆方非公开素材(图录扫描、内部讲解词)?** — 这是 ADR-003 未覆盖的灰区。**Researcher 立场:这条边界由 PM 决定,本质上是「私人关系帮忙 ≠ 馆方授权」,放进作品集时如何叙述是关键风险点**。
