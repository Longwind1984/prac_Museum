## v4 vs 我 R3 骨架的兑现度(诚实)

我 R3 骨架给了 5 块:**5 触点 + 触发条件表** / **1px 呼吸金点 + 长按 1.5s 露下次** / **PS 段 12 卡滑动 + 拖到底自我关闭** / **anchor set 一次 + 永不 recall(只作 PS 背景图极淡铺底)** / **删 TOC / 删 export / 删上一步**。**实现完成度 ~75%,但有 3 处偏离骨架值得点名,1 处偏离反而是对的。**

### 1. 实了 + 实得干净:呼吸金点 + 长按 1.5s 露下次 + 短按召唤

`breath-dot` 1×1px,`@keyframes breath` 0.4 → 1 opacity,我骨架写的"6 秒周期 0.2 → 0.5"被改成"4.2 秒 0.4 → 1"——**周期短了,亮度上限拉高了**。这是 builder 在执行时的现场判断,可能合理(1px 在 6s/0.2 下用户在博物馆白天根本看不见),但**这等于把"几乎错觉"的姿态主动调亮了**——v4 已经在自己软化我骨架的"几乎不在"押注。`pointerdown` + setTimeout 1500ms 实现长按区分,短按则进触点——逻辑完整。**长按区分阈值用 setTimeout 而不是 pointerup 时间差**,虽然能 work,但 didLongPress flag 的判定有竞争条件嫌疑(快速点击 + 长按混合时可能出 bug)——工程债,但 dogfood 场景能扛。

### 2. 实了 + 实得贴合:5 触点的具体内容 + 触发降级

5 触点 id 完整保留(`pre / maya-jade / sipan-burial / synth-sharp / next-day`),措辞**几乎是 v3 同卡的 1:1 复制**——这意味着 v4 没在内容上重新发力,押注完全在形态。骨架原定"用户主动唤起 + 时间窗"被简化成 `suggestedTs` 字段 + `isPastSuggested()` 函数——**只看时间过没过,不看用户实际行为**。我 R3 骨架第 3 触点 sipan 设想的"用户进厅 + 出厅一次再开"完全没实现,降级为"14:30 后任意时间可开"。这是合理简化(动态触发的代价 v3 已交过学费,v4 没必要再交),但**等于承认了"用户主动按时间进 5 张卡"和 v1 的"按 next 进 17 张卡"在引擎上是同一个东西**——只是卡少了 12 张,装饰少了一层,姿态从"按部就班"变成"按部就班且黑屏"。**我 R3 骨架第 5 段说的"5 触点之间用户主动唤起"在 v4 里是真的,但'唤起'只是'到时间了按一下点'——这不是真触发,是定时器变成了用户手动 trigger**。

### 3. 偏离 + 偏离对了:PS 段不是滑动条,是滑动卡片(12 + 1 final)

骨架原文"`[----●------------------]` 滑块 + 拖动看一件"是物理滑块。v4 实现成 `ps-scroll`(横向 scroll-snap)+ 12 张卡片 + 1 final 卡。这**更好**——滑块的"拖动条"在小屏交互上有歧义(是音量?是进度?),scroll-snap 是 mobile 通用的"卡片 carousel"语义,用户立刻知道怎么用。`ps-dots` 也比"滑块进度刻度"更轻。**这处偏离比骨架更合理,接受**。但 final 卡上的"读完了 · 关掉"按钮 + "明晚见"的 closed 页**比骨架还要更显式 narrate**——我骨架原话"app 自我关闭",意思是悄悄退出 / redirect 到一个不动的静态页;v4 做成了"读完了 → 关掉按钮 → 明晚见 + 不要回头打开"——**这又是一处用文字 narrate 克制**。**v4 在最后一屏不小心做了 v3 的病**。

### 4. 偏离 + 偏离值得评估:anchor 处理 — 写在 pre 卡的 textarea 里,而不是独立 anchor 字段

我 R3 骨架的"anchor set 一次 + 永不 recall + 只作 PS 背景图极淡铺底"——v4 第 663 行 `if (tp.anchor === 'set') state.anchor = ta.value` 实现了"pre 卡的 textarea 双重写入 anchor"。**功能上对**:用户在 pre 卡写下的那段同时存为 `state.notes.pre` 和 `state.anchor`,PS 段右上角用 `opacity: 0.06` 极淡铺底——骨架兑现。**但 anchor 字段和 notes 字段的耦合让"anchor 是独立的画面"这个语义弱化**——用户在 pre 卡看到的就是一个普通 textarea,没有任何 UI 信号告诉他"这一句话和其他 4 个触点的 note 不一样"。**v4 没让用户感觉到 anchor 的特殊性,等于 anchor 在体感上消失了**——这正好兑现了"AI 不还给用户"的姿态,但**用户也不知道自己写的是 anchor**。这是个微妙的 trade-off。

### 5. 偏离 + 偏离偏离错了:dev export 7 条问题里有"v4 vs v2/v3 哪个最像朋友"

v4 export 第 6 条:**"v4 vs v2/v3:哪个版本对你而言最像「朋友」?"**——这条问题**只有团队成员能回答**(外部用户不知道 v2/v3 长什么样)。这是 v4 隐性承认了 dogfood 本质,**但承认得不彻底**:export 仍藏在三击顶部里,前端伪装成"对外可用产品",反馈表却问"你认得 v2 v3 吗"。这是 R2-C(研究员模式)的偷偷半实现——但因为是偷偷,**既没拿到 R2-C 的反馈密度红利,也破坏了 v4 的"AI 真的不在"沉浸**。值得 v5 决断:**要么彻底 surface dogfood,要么彻底拿掉"v2 vs v3 vs v4"这种内部 framing 的问题**。

### 6. 没实但本来骨架就让步了:中央位置改成"底部偏上"

骨架原文"屏幕正中央 1×1 像素的金点"。v4 第 53-61 行 `bottom: calc(80px + var(--safe-bottom))` —— **金点在底部 80 px**,不在正中央。这是合理的 ergonomics(底部更接近拇指),但**正中央的金点是"AI 在你眼前"的视觉哲学**,底部金点是"AI 在你手边的备忘按钮"。**这一刀切下去,AI 的位置感从"凝视"变成"调用"**——本质从同伴变成 widget。**不是 v4 的错,但是 v4 没注意到的一步降级**。

### meta · v4 总评

**v4 是 R3 骨架的诚实落地版本,但比骨架更软**——它没保留"凝视的金点"(中央 → 底部)、没保留"几乎错觉的呼吸"(0.2-0.5/6s → 0.4-1/4.2s)、没保留"app 自我消失的姿态"(redirect 静态页 → "关掉"按钮 + "明晚见")。**3 处软化,每处都是 builder 在工程现实里"为了不让用户以为 app 坏了"做出的让步**。这正是我 R3 骨架最后段元问题里指出的方向:**"显式状态吊牌 vs 完全不可见,前者安全,后者诚实"**——v4 在每一个具体决策上选了"中间偏前者"。结果是 v4 比 R3 骨架描述的版本姿态弱了一格,但**工程上能 ship、用户上手不会懵**。这是 PM-sense 的胜利,**也是哲学押注上的退一步**。

**给 v5 的启示**:**v4 是"姿态的极致"和"工程的可用"之间的中间路线**。如果 v5 押"再激进一档",会失去 v4 的工程可用;如果 v5 押"再缓和一档",会回到 v3 的 narrate 克制。**v5 必须找一条不在这两端的轴**——不是"AI 更不在"也不是"AI 更礼貌",而是 PRD §6 人格里**v1-v4 都没真做的那一块**(下面具体说)。

## v5 押注哲学(我的选择 + 反对意见)

### 5 条候选押注重新摆出来

1. **押"克制内容,深开 2-3 次"**(v2 + v3 余韵):从 5 触点压到 2-3 触点,每次都是真的深开,内容立场更重。
2. **押"AI 几乎不存在,做 negative space"**(v4 极致):比 v4 更稀疏,可能 1-2 个开口。
3. **押"AI 是注意力雕塑家"**(R2-A 高亮代替开口):AI 不给信息,只 highlight / fold / dim 用户已经能看到的内容。
4. **押"AI 是回声壁"**(R2-B 被动响应):用户写完就被 echo,AI 完全不主动。
5. **押"承认 dogfood 本质"**(R2-C 研究员模式):surface 两层 = 产品 + 元产品。

### 我的押注:**1 + 5 的合成,核心是 1**(押"克制内容 + 跨次记忆 + 立场" + 同时 surface dogfood 但不是显式 chip)

**为什么是 1 为核心,而不是 2 / 3 / 4**:

- **2(更稀)**:v4 已经走到了"用户能否容忍 AI 不在"的临界点(R3-A 写过,4 小时只见 2 次面)。再走一档是"测试不存在的产品"——但**PRD §6 人格本身要测的是"AI 同伴说了什么 / 怎么说"**,不是"AI 同伴在不在"。v4 已经把"在"压到极限,**v5 反而应该回头测内容**。
- **3(注意力雕塑家)**:R2-A 的核心问题至今没解 — "AI 没有立场没有知识,只有强调权"等于把 PRD §6 的"立场"原则彻底放弃。**与本项目"反讲解员 + 有立场"的内核冲突**。不押。
- **4(回声壁)**:R2-B 拿到的是"想念指标",但**测不到内容,测不到立场**——4 小时下来 AI 一共说了 100 字,这 100 字还是字符串模板替换。**和 PRD §6 人格"承认争议、自暴露偏好、有立场"完全不相容**。不押。
- **5(研究员模式)**:R2-C 是 surface dogfood,但**它不是核心押注,它是一个 instrumentation 选择**(怎么收反馈),不是产品哲学押注。它可以叠加在 1/2/3/4 任何一条上。**5 进 v5,但不是 v5 的核心。**

**为什么是 1**:

v1-v4 走过的轨迹是:**v1 多说 → v2 少说 + 节流 → v3 礼貌说 → v4 不说**。这 4 步里**没有一步是真正回到"我说什么 / 为什么这一句是这一句"**——v2 critic-led 是"节奏修",v3 是"礼仪改造",v4 是"删减到几乎为 0"。**4 个版本对"内容质量"的迭代是 0**——maya-jade 那段"玉 = 玉米"从 v1 到 v4 一字未改。**4 个版本里 AI 说的话,本质上还是 v1 PM 一稿写完的那 9 个开口的子集 / 删减版**。

**v5 应该回到内容**——但**不是回到 v1 的多内容,是回到内容的"立场颗粒度"**。

具体来说:**v5 押 "AI 是有 3 件具体不同意的事的同伴"**。
- AI 在 v5 里**只有 3 个真开口**(数量介于 v4 的 5 和 R3-A 的 2 之间)。
- 这 3 个开口**每一个都是 AI 显式反对某种主流博物馆叙事**:反对"玉=君子"叙事 / 反对"西潘 = 印加" / 反对"精灵"翻译姿态。
- AI 的开口不是中性陈述事实,**是有立场地说"我不同意这个说法"**——这是 PRD §6.2 第 4 条("有立场但不傲慢")v1-v4 一直没真做的兑现。
- AI 的"克制"不再用"少说"或"不在"表达,而用**"我只在我有真意见的时候开口"**表达。**克制 = 立场密度 / 字数,不是字数本身**。

**这是 v1-v4 真正缺的那条**。v1 说话多但立场弱(措辞文艺),v2 说话节流但措辞和 v1 一样,v3 礼貌但姿态空,v4 不说话所以根本谈不上立场。**v5 是"AI 终于真有意见了"的版本**。

**配合 5(dogfood surface)的方式**:不是开关 chip,也不是 collapsed details——而是**v5 默认开启"批注模式":每个 AI 开口下方有一行 9px 灰字,标 PM 自己的"我为什么这一句是这一句 / 我犹豫过什么"**。**只有 1 行,不能 collapse**——它就在那。dogfood 用户看到了拿来作反馈;真要给外部用户看就把那一行 hide(配置 flag)。**这不是研究员模式的"对照",这是产品哲学的脚注**——和正文同等重要。

### 反对意见(诚实)

1. **"3 件不同意"听起来像新增 mechanic,违反 v4 的"删"路线**。反驳:v5 不是删 v4 的删,**是把 v4 删完之后留下的 5 个开口换内容**——总量仍是 3-5 个,字数仍是 v4 量级。**5 改 3 是再删,不是加**。
2. **"AI 有立场" PM 早写在 PRD §6.2 第 4 条,v1-v4 都 claim 实现了,v5 凭什么说"终于真做"?** 反驳:实际看 4 版的 ai.body,maya-jade 那段是"玉 = 玉米 = 王权"——这是**事实陈述**,不是"我倾向认为 X,但你也可以从 Y 反驳"的立场。**立场需要 "我不同意/我倾向/我犹豫" 这种第一人称判定动词**,4 版里几乎一个都没有。**v5 把这一格补上,是真补,不是 reframing**。
3. **批注模式 = 又一种"narrate 立场"的陷阱**。反驳:批注模式不 narrate 立场(立场在正文 ai.body),它 narrate 的是**"PM 的选择过程"**——这本质是元产品维度,不是产品维度。把"我犹豫过""我删过什么""我换过哪个词" surface 出来,**是诚实把"产品是怎么造的"作为产品的一部分** —— **这是反 v3 status badge "narrate AI 在做什么"的关键区别:status badge narrate 的是 AI 实时状态(假),批注 narrate 的是 PM 决策痕迹(真)**。
4. **3 个开口太少,4 小时撑不住**。反驳:3 个开口 + pre 段 + next-day 段 = 5 段(总数和 v4 一样),但**中间 3 个开口承载的"我有意见"密度是 v4 的 3 倍**——单次开口含金量 ≠ 开口数。
5. **批注会破坏沉浸**。反驳:批注 9px,只 1 行,放在 AI 开口正文下方——比 v3 status badge 的 5 状态轮换或 v4 的"明晚见"导师腔都更隐蔽。**而且批注本身是 v5 押注的一部分**:这次产品 = 一个有立场的 AI + 一个有立场的 PM。两个立场互相校验。

### Orchestrator 的决策线(2 个版本不能同时押,只能 1 个)

| 押什么 | 谁的本子 | 风险 | 测得到的关键问题 |
|---|---|---|---|
| **(我推 v5)立场密度 + 批注** | R4 Innovator | 内容工作量 ×2(每句都要重写到"有立场") | "AI 终于真有意见了" 是不是同伴的真正核心? |
| **v4 + 修 3 处软化** | v4 builder 自然演进 | 仍是"AI 不在"的赌注,但 patch 一下中央位置 / 关闭页姿态 | v4 push 到极致后用户能扛吗? |
| **R3-A 极致稀疏(2 触点)** | R3-A | 测不到内容,只测"完全不在的容忍" | 0 次主动开口的产品还能叫 AI 同伴吗? |

**Orchestrator 不能同时押任意两个**——v5 立场密度方向需要重写所有 ai.body,v4 + patch 是改 100 行 CSS,R3-A 是改 TPS 数组结构。**任何两条同时押都是缝合怪**。

**我建议押(我推 v5)**。理由在下面"留给 PM 的元决策"段。

| 1 | **17 触点 linear + 多模态默认** | v1 | **不进** | 17 触点是讲解员频率,多模态默认是堆砌嫌疑——R1 critic 已修干净。v5 仍是 5 触点结构。 |

| 10 | **status sheet(等什么 / 猜在哪 / 配额)** | v3 | **不进** | 同上。这是 status badge 的延伸。v5 不要。 |

## v5 设计骨架(具体到 Orchestrator 能 1 turn 写完)

### 触点结构

5 个触点,**形态学和 v4 完全一致**(数组 TPS,每张卡有 id / label / time / suggestedTs / sys / ai / action / askPlaceholder / next):

| # | id | label | time | ai 的形态 |
|---|---|---|---|---|
| 1 | `pre` | 出发前 | 11:30 | sys-text(背景信息) + anchor textarea。**AI 不开口**。 |
| 2 | `against-jade` | 我不同意 1 · 玉 | ~12:35 | 1 个开口。**AI 显式反对"玉是君子"叙事**。 |
| 3 | `against-sipan` | 我不同意 2 · 西潘 | ~14:30 | 1 个开口。**AI 显式反对"安第斯古代 = 印加"叙事 + 反对"同葬说明牌写得轻"**。 |
| 4 | `against-translation` | 我不同意 3 · 翻译 | 15:50 | 1 个开口。**AI 显式反对"精灵"中文翻译的去神化姿态**。 |
| 5 | `next-day` | 次日 · 一个问题 | T+1 晚 | 1 个问句。**AI 问的是"你今天最不同意我哪条"——不是同伴谈感受,是同伴邀请你反驳**。 |

**关键差异 vs v4**:
- v4 中段 3 张卡是"AI 给信息"(玉 = 玉米 / 1987 抢救 + 同葬数字 / 隐含翻译姿态没显式说)。
- v5 中段 3 张卡是"AI 说我不同意 X,我倾向 Y,但你可以从 Z 反驳"。**每一段都有 "我倾向" / "我不同意" / "我犹豫" 这种第一人称立场动词,共 ≥3 处**(对照 v4 ai.body 一处都没有)。
- next-day 从"只跟一个朋友讲昨天的一件事"改成"你今天最不同意我哪条"——**核心反讲解员的兑现:邀请用户反驳同伴**,这是 PRD §6.2 第 4 条"有立场但不傲慢"+ 原则 C(觉察叙事背后的权力结构)的合流。

### AI 开口策略

- **0 次主动 surface**——所有开口都需要用户短按金点进入触点。
- **每次开口 = 一次显式不同意 / 一次倾向陈述 / 一次邀请反驳**(三件套)。
- **不分"重开口 / 轻开口"** —— 要么开口(有立场),要么不开口(那张卡不存在,跳过)。
- **删 mode-shift "我说一句吗"** —— AI 不问门。AI 已经决定要说了,因为他有意见。

### Anchor 处理

- `pre` 卡 textarea **视觉区分**:相比 v4 的普通 textarea,v5 给 anchor textarea 一个左侧金色细线(1 px,v4 的 ai-speak 用 3px 金线,这里用 1px——视觉上"小一号的庄重")+ placeholder 改为"今天进馆前,你脑里浮现的一个画面。这一句话之后 4 小时不再出现。"
- **设一次,不 recall,不 echo**——和 v4 完全一致。
- PS 段背景图 opacity 0.06 极淡铺底——和 v4 完全一致。
- **新增一处**:closed 页(明晚见的那一页 v5 改文案后)右下角 12px 灰字一行:"你 12:00 写的那句话:____"(显示用户 anchor 全文)。**不点击,不操作,就是显示**。**这是 v5 唯一一处 anchor 显式回到用户面前——但发生在 app 已经关闭之后**。是"AI 不还给用户"和"用户离开前最后一眼自己写的"的折中。**风险**:可能违反 v4 "永不 recall" 的纯粹性。**Orchestrator 自决**——这是元决策 1。

### Modality

- **纯文字**。无 photo,无 voice。
- pre 卡 textarea + 3 中段触点 textarea + next-day textarea = 5 个 textarea,**完全继承 v4**。
- v1-v4 的多模态争议在 v2 critic 已经盖棺(默认隐藏),v5 不再讨论。

### dogfood 反馈通道(R2-C 的折中实现)

- 批注模式 = 每个 ai-speak 块下方 9px 灰字一行,写 PM 自己的"我为什么这一句是这一句 / 我犹豫过什么"。
- 默认**开启**(v5 实测对象 = 团队成员,假装外部用户没意义)。
- 配置 flag `?guest=1` URL 参数关闭批注——给外部用户(实测后)看的版本。
- **批注绝不超过 1 行 80 字符**,绝不能 collapsed(因为 collapse 等于藏起来,batch 起来藏起来等于"看后台",会让产品分层成"前台 / 后台",**那是 v3 status sheet 的病**)。
- export 拆 user / team 两份(回到 v2 split-export):
  - 用户日志:正文 + 笔记,**无批注**。
  - 团队反馈:正文 + 笔记 + **批注** + 5 问反馈(见下)。

**团队反馈表 5 问(替换 v4 的 7 问)**:
1. 3 段"我不同意"里,哪一段你觉得 AI **真的有立场**?哪一段你觉得是 PM 在替 AI 装腔?
2. 批注模式的存在让你觉得 (a) 诚实 (b) 出戏 (c) 没注意?
3. next-day 那个问题"你最不同意我哪条"——和 v4 的"只跟一个朋友讲一件事",哪个更想答?
4. v5 vs v4:**AI 在 v5 里说了更少的话(总字数减半),但说的话更有立场**——你倾向哪个版本?
5. PRD §6.2 第 4 条("有立场但不傲慢")在 v5 里的兑现度,你打几分?(1-5)

### 视觉 / 时序

#### 视觉

- **CSS 99% 继承 v4**。改 3 处:
  1. `.breath-dot`:从 `bottom: 80px` 改回 `top: 50%; left: 50%; transform: translate(-50%, -50%)`(屏幕正中央)。
  2. `@keyframes breath`:从 `0.4 → 1 / 4.2s` 改回 `0.2 → 0.5 / 6s`(几乎错觉)。
  3. 新增 `.pm-note`:`font-size: 9px; color: var(--dim); letter-spacing: 0.04em; margin-top: 12px; padding-left: 24px; opacity: 0.55;` —— 批注样式。
- closed 页改文案:删"明晚见 / 关掉 / 不要回头打开",只留:**纯黑屏 + 屏幕正中央 9px 灰字一行 "今天的 app 已过期" + 右下角 12px 灰字一行 anchor 显示**。
- PS 段 12 卡砍到 6 卡(具体哪 6 卡见 mechanic 表 #15)。

#### 时序

- `suggestedTs` 字段保留(沿用 v4 的 `isPastSuggested` 判定)。
- pre:任何时间可进。
- against-jade: 12:30 后可进。
- against-sipan: 14:30 后可进。
- against-translation: 15:50 后可进。
- next-day: 任何时间可进(但用户至少要完成 4 张前序才能进——v4 已有 idx 顺序保证)。
- **时间窗外短按金点**:显示 peek-time(沿用 v4 实现)。
- **完成 5 张后**:自动进 PS 模式(沿用 v4)。
- **PS 6 卡滑到底**:closed(沿用 v4 框架,但文案如上改)。

#### 中央金点(关键的一处比 v4 严格)

v4 的金点在底部 80px——v5 改回正中央。**论据**:
- 中央 = "AI 在你视线中央"——凝视感。
- 底部 = "AI 在拇指可及处"——工具感。
- v5 押"AI 是有立场的同伴",**他的位置应该在你眼前而不是你手边**。
- 用户进 app 第一眼看到的不是"一个待机的按钮",是"一个不说话但在看你的点"。

风险:中央金点 + 小屏幕 + 黑色背景 → 在户外阳光下用户可能看不见。**接受这个风险**——这正是 v4 软化的方向 v5 不再软化的体现。如果用户找不到金点 → 长按屏幕任何位置仍可触发 peek-time(v5 新增的 fallback,实现成本 ~5 行)。

## 留给最终 PM 的元决策(1-2 个 hard call)

### 元决策 1【主决策 · 极重要】

> **v5 让 AI 终于"有意见"——这是把 AI 从"克制的同伴"推到"有立场的同伴"。但 PRD §6.2 第 4 条说 "有立场但不傲慢"——v5 的"我不同意 X,我倾向 Y"措辞,落在 5/18 实测场景里会不会被团队 dogfood 用户读成"AI 在替 PM 输出政治观点"?**
>
> 尤其是 against-translation 那段——"翻译姿态 / 谁替你决定古代美洲人信什么"在大陆语境下,虽不直接踩 T2(没说政治),但接近原则 C 边界。**PM 必须拍板:v5 要不要保留 against-translation 这一卡?**
>
> 三个分支:
> (a) 保留 3 卡 all in("我不同意"是 v5 押注的全部,缺一退化为 v4)——**我推荐**,理由:这次 dogfood 用户全是团队,不存在"误伤外部"的风险;原则 C 本身就是项目核心原则之一,v1-v4 都没真兑现,v5 不做下一版也不会做。
> (b) 保 against-jade + against-sipan,删 against-translation,改成"中性触点"(回退 v4 的 synth-sharp"挑 1 个不对劲")—— 安全,但 v5 押注稀释 1/3。
> (c) 全保留,但 against-translation 措辞软化("我倾向认为'精灵'比'灵魂'轻 → 我倾向认为'精灵'这个选择有它的代价") —— PM 自己改一遍措辞,这是元决策 1 的妥协版。
>
> **这一决定决定 v5 是 v5 还是 v4.1**。

### 元决策 2【次决策 · 中等重要】

> **anchor 是否在 closed 页右下角"还给"用户一次?**
>
> v4 押"anchor 永不 recall,画面是用户自己的"——但 v4 实测后(待 5/18 数据)如果反馈是"我都忘了我 12:00 写了什么 / 不知道 anchor 这个机制有什么用",v5 的"closed 页右下角 12px 显示 anchor"是温和的折中——**它在用户准备关 app 时让他最后看一眼**,既不"主动 recall"(没有打断 / 没有引用 / 没有要求回答),又给了"画面在产品里活过一次"的证据。
>
> 这是一个 v4 没做过的微妙姿态——**它要不要做,PM 拍板**。
>
> (a) 做 —— anchor 在 closed 页右下角 12px 一行显示,纯展示,不交互。
> (b) 不做 —— 完全继承 v4 "永不 recall"——anchor 只在 PS 背景图 opacity 0.06 出现,closed 页不出现。
>
> 我倾向 (a)——理由是:**这一次显示是"AI 把画面还给你",姿态上和 PRD §6 "同行的资深爱好者"相容**——朋友会在分别时说"你之前提过的那件事,你说怎么样?"——他不强求回答,但他记得。**这是 anchor 机制的"温度兑现"**,v1-v4 始终没做对的那一格。

### 元决策 3【小,但 v5 必决】

> **批注模式默认开 vs 默认关?**
>
> 我骨架押"默认开,?guest=1 关"——理由:5/18 实测用户全是团队,默认开拿到最高反馈密度。
> 但 PM 也可以反过来:默认关,?team=1 开——理由:**默认状态应该是产品对外的样子**,而不是 dogfood 模式。
>
> 两种都可执行。我倾向"默认开"是因为这次实测不会有外部用户,但 PM 如果想"先伪装成对外产品再切研究员模式",反过来配置即可。

## meta · v5 押注 vs v4 押注的本质区别
