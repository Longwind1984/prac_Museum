## v2 vs v1:它失去了什么(诚实)

Critic-led 整改在 PM-sense 上明确进步——但凡 critic-led 都会带 4 种副作用,v2 全中:

### 1. 失去了"我开口"的密度起伏 → 节奏变平

v1 是 9 次开口压在 4 小时,有的厅 3 次叠着开(玛雅厅密集),有的厅 0 次(spirit-laugh 整段沉默)。v2 砍到 8 次开口 + 4 显式沉默,**几乎一厅一次**,均匀化。结果是:虽然总量没少,**但"忽近忽远"的体感被磨平了**——朋友变成节拍器。Critic 修掉的"装腔"和这个**密度起伏**是同一刀切下来的,顺手切到了节奏。

### 2. 失去了"模糊地带" → 每个块都被命名得太干净

v1 里 silence 是隐式的(屏幕该静就静);v2 把 silence 显式做成 `.ai-silence` 组件,加 `<em>我先不说话</em>` 字样。**这是悖论**:为了表达克制,反而 narrate 了克制本身——"看,我在克制哦"。一个真正克制的产品**不会指着自己说"我克制"**。同理,`chipKind: 'silent'` 这种分类、TOC 里 `silent` muted 样式,把"沉默"做成了一个**显式频道**,而沉默的本质是"无频道"。

### 3. 失去了 anchor 的私密性 → 它被升级成了 mechanic

v1 的 anchor 是 12:00 一句话,在 15:55 被回看,**就一次**。v2 加了 `aiEcho`(14:50 中途引用)+ `aiAnchorRecall`(15:55 回看)+ Export 里头部专门一栏。anchor 从"一句藏在脑里的话"变成了"被产品 surface 3 次的 KPI"。**Critic 把它做成了 Agent mechanic 的展示橱窗**——技术上证明了"AI 记得你写的",但**这件"被记住"的事被讲了 3 遍,就不再像被记住,像被记录**。

### 4. 失去了"测试用户作为人"的余地 → 它变成"测试用户作为受试者"

v2 的 break 卡 `autoPause: 30*60` 是强制锁死的——继续按钮 30 分钟不可点。v2 的 throttle 是 60s 强制消化(虽然给了"我看到了"逃生口)。**这两个机制本身是 critic 对的判断**(用户会不会真休息?会不会真消化?),但叠加起来,**产品对用户的不信任浓度上来了**。v1 是"我说了你自己看着办",v2 是"我说了+我锁着不让你跳"。这和 PRD §6 "朋友"姿态在哲学上拉扯。

### 5.(次要)失去了多模态作为"默认存在" → 它成了奖励物

v2 把"加照片"按钮**默认隐藏**,只在 `spirit-translation` 卡 `allowPhoto: true`。Critic 的理由可能是"多模态不该到处都在"。但反面是:**多模态本来是用户表达情绪 / 笑点 / 顺手记的最低门槛通道**,被收回后,用户在前 7 个触点想拍一张就拍不了。**这把"记笔记的多样性"换成了"产品克制的整洁感"**。

**meta**:这 5 条里,1-2-4 是同一种病——critic 倾向于**用结构去 narrate 立场**。v3 必须警惕:**真克制不命名自己**。

## 给 v3(动态触发)的设计骨架

> 已锚定方向:R1 提案 3 "时间 + 位置 + 笔记输入 + 静默 动态触发"。下面给可执行骨架。
> 关键约束:不踩 T3(不申请位置权限可能触发后端 / 不开任何对外发信);仅 client-side。

### 状态机层(必须先固化,然后再决定 UI)

整个 v3 跑在一个**显式状态机**上,而不是 v1/v2 那种"linear TPS 数组 + 用户按 next"。

**状态(state)**:
- `pre_depart`:出发前
- `transit`:路上
- `arrived_lobby`:入馆大厅
- `in_hall_<id>`:某厅内
- `between_halls`:厅间走廊
- `break`:中场
- `final_synth`:综合(最后一厅出口前)
- `post_visit`:离馆
- `next_day_pending`:次日反馈窗口

**事件(event)能让状态迁移**:
- 用户**显式声明**(下拉里点"我现在在 X 厅" / "我要休息了" / "我出馆了")—— **必须有**,这是 fallback,不依赖任何 sensor
- 用户**写笔记**(写超过 N 字)
- 用户**停留时间累计**到某阈值
- 用户**长时间无操作**(静默)
- (可选)用户**主动上传位置**(粘贴一次"我在首博"的 GPS 坐标——一次性,不持续追踪)

**核心原则**:状态机是单向流动的(可手动回退,但默认前进)。**显式声明永远是 ground truth**——sensor 只是"如果用户没说,我猜"。这一条避免了"AI 自动断你在哪"的家长式风险。

### 引发条件(每条都给具体事件 + 措辞示例,Orchestrator 实现时可直接抄)

> 共 6-8 个真"开口",但**没有任何一个时点是固定的**。每个开口绑定的是"什么情况下我开口",不是"几点开口"。

| 开口 | 引发条件(精确) | 不引发的情况 | 大意措辞 |
|---|---|---|---|
| **A · 出发前(玉的预告)** | `pre_depart` 状态 + 用户写完 anchor(textarea blur 且 ≥6 字) | anchor 没写完 | "今天玉会反复出现。先记一下你脑里的玉是什么。等会儿再看。" |
| **B · 入厅后首次玉器停留** | `in_hall_maya` + 用户主动点"我在看玉器"的 chip | 用户没点 / 在玛雅厅但没看玉 | "玉 = 玉米 = 王权 = 生命的呼吸。" |
| **C · 西潘 1987 触发** | 用户在 `in_hall_sipan` 状态停留 ≥ 8 分钟 **且** note 里没出现"盗"/"1987"任一字 | 用户已经自己写到了 | "1987 才挖出来。盗墓贼手里抢回来的。" |
| **D · 同葬触发** | 用户 note 里出现"葬"/"陪"/"殉"/"埋" 任一字 | note 里没这些字 → 不主动开口 | "3 个女人 2 个战士 1 个男孩 + 羊驼。说明牌大概率写得很轻。" |
| **E · anchor 静默回声** | 进入 `between_halls` **且** 累计游览时长 ≥ 2.5h **且** 用户 anchor 非空 | anchor 空 / 用户刚刚写过 note(< 5 分钟) | (引用 anchor 原文)"这一行字到了现在。你自己接。" |
| **F · 翻译姿态(精灵)** | `in_hall_spirit` + 用户深看过任一动物展品 ≥ 3 分钟 | 没深看 → 不开 | "中文叫'精灵'。原文大概率是 espíritu。去神化了。" |
| **G · 综合 · 最尖锐** | 用户**显式声明**"我要离馆了" → 此刻开 | 用户没声明,纯靠时间猜 → 不开(避免误判) | "挑 1 个不对劲。一句话。" |
| **H · 次日** | 设备时区当地时间 = T+1 19:00–23:00 区间内用户首次重新打开页面 | 用户没回来 → 永远不主动 surface(没有 push 能力) | "只跟一个朋友讲今天的一件事,你讲什么。" |

### 不引发条件(同样重要,且是 v3 区别于 v1/v2 的真特征)

**这一段是 v3 的灵魂。如果只看引发条件,会以为是"更聪明的剧本"。但 v3 的克制是 negative space——什么时候 *不* 开口比什么时候开口更重要。**

- **用户连续写笔记 > 30 秒**:任何 pending 的 trigger 都暂停,**不打断**。等用户连续 60s 不输入再考虑。
- **用户刚 blur 一次 textarea < 90 秒**:不开口(他刚说完话,让他喘)。
- **用户在同一卡 < 3 分钟**:不开口(他还在适应)。
- **用户连续 2 次主动 dismiss 了同类 trigger**:这一类 trigger 当天封口(用户在告诉你"别这样了")。
- **静默 > 25 分钟但用户处于 `break` / `in_hall_*` 已超 45 分钟**:**不**自动 ping(他可能是在深看,不是丢了你)—— 这是反 v2 throttle 哲学的关键一条。
- **anchor 还没写**:整个 anchor 相关回声链(E)沉默(不能"提示用户你忘了写 anchor"——那是讲解员)。
- **用户没显式声明状态、且 sensor 不确定**:**默认不开口**(沉默比误开口便宜)。

### UI 表达:用户怎么知道 AI 此刻在"等"什么

> v2 的 12 触点列表 + progress bar 让用户随时知道"走到几分之几"。v3 没有线性进度——所以**必须**用另一种方式让用户"读懂 AI 状态",否则会感觉 AI 失控 / 不在 / 故障。

**主屏永久组件:状态吊牌(status badge)**

屏幕右上角一个 28×28 的小圆点 + 一行 10px 文字。永远在那。不点开就只是一个点 + 状态词:

- `· 我在听` (默认,无 pending trigger)
- `· 我在等你` (有 pending trigger,但正在被 negative-space 规则压住)
- `· 一会儿说` (trigger 已激活,正在节流冷却中,< 60s 内会 surface)
- `· 现在` (开口正在屏幕中段)
- `· 不在` (用户进入 `break` / 主动调成"勿扰")

**点开吊牌 → 半屏 sheet,显示 3 行**:
1. **AI 此刻在等什么**(人话):"等你在玛雅厅再待 3 分钟,或等你写一句 note。先到的先来。"
2. **AI 当前对你状态的猜测**:"我猜你在玛雅厅(你 12:18 显式声明的);如果不对,点改。"
3. **静默配额**:"今天还可以主动 ping 你 2 次。"

这一组件做对了 4 件事:
- 让"动态触发"对用户**可见而非神秘**(否则会觉得 AI 在玄学开口)
- 把"AI 没说话"明示为**主动的状态**(`我在听`),不是"产品坏了"
- 给用户**改正 AI 误判**的入口(状态猜测可点改)
- 把"AI 主动 ping 你"这种**可能讨厌**的能力,做成了**有配额的、用户能看见余额的**机制——这是反 v2 throttle 家长姿态的最重要一招

**额外:开口出现时的 mode shift**

v2 是直接渲染 `.ai-speak` 块,无过渡。v3:开口出现时,**先在底部冒一行 12px 的灰字**"我说一句吗"+ "等等" / "好" 两个按钮。**用户点"好"才 expand 成全文**。这把"AI 主动开口"从 push 改成 confirmed pull——一句话变两秒,但**用户控制感拉满**。

> 这一改动也是反 v2 throttle 的——v2 用"消化时间锁"逼用户停一下;v3 用"先打招呼再说话"让用户**主动 invite**。同样达到"不被信息浪冲走"的目的,但姿态从 paternal 变成 polite。

### 不该做的事(给 Orchestrator 的红线)

- **不要**搞 geolocation API(踩位置权限弹窗,在大陆语境下当场流失)
- **不要**让"显式声明状态"变成一个 14 个 chip 的下拉(太重)。最多 5 个 chip:`大厅 / 玛雅厅 / 西潘厅 / 精灵厅 / 已出馆`
- **不要**显示"还剩 X 个开口"这种 progress(这是 v2 的 12 触点叙事,v3 抛弃)
- **不要**把 `静默配额` 设成 0(用户主动调"勿扰"除外)。0 配额 = v2 的 critic 极端,产品就死了
- **不要**写 `console.log` 之外的 telemetry —— v3 仍是 0 上报

## 额外 reframe 提案(更狠)

### 提案 R2-A · 把 AI 的"开口"从"显示文字"改成"删用户已经看到的内容"(中度激进)

**核心想法**(≤ 30 字):
AI 不增加内容,AI 减少内容。

**最辣的设计实现细节**:
- v2 / v3 默认状态:屏幕里有 5-7 段 user-facing 文字(intro / user action / note placeholder / 历史 note 回看)。
- AI 的"开口"不是 ai-speak block 蹦出来,而是**屏幕上某一段已经存在的文字,被划掉一行 / 加重一个词 / 折叠成一句**。
- 例:在西潘厅,intro 原文里有"主墓 451 件随葬器物,3 女 2 战 1 男孩 + 羊驼"。AI"开口"时,**屏幕上这一行从黑色加粗变成金色,其他文字 dim 20%**,持续 4 秒,然后还原。
- 整个产品里 AI **没有一个新句子**——所有内容都是用户自己已经能看到的,AI 只做 **highlight / fold / dim / strike-through**。
- 离馆后 outro,AI"开口"=**把整篇 outro 里 80% 的字 dim 到 var(--faint),只留 2 行高亮**。AI 的告别是"我把今天的话收回去,只留 2 句给你"。

**它 reframe 了什么**:
- v1/v2/v3 的所有"AI 开口"都假设:**AI 提供信息**。这版假设:**AI 不提供任何新信息,AI 是注意力的雕塑家**。
- 直接挑战 PRD §6 "立场 + 知识" 的内容供应模型——这版的 AI 没立场没知识,只有**强调权**。
- 强化原则 B(反讲解员):讲解员的本质是"给你不知道的信息";这版的 AI 物理上**无法**讲解。
- 部分挑战原则 D(知识结构):知识结构在这版里是用户自己构建的,AI 只**指**结构里的某条边。

**风险 / 反对意见**:
- 测不到"AI 同伴能不能撑住"——这版 AI 几乎没人格,人格被压缩进 highlight 的节奏感里,可能太弱。
- 视觉效果在小屏 + 弱光环境下可能看不清(dim 20% 在户外阳光下就废了)。
- 实现复杂度比 v3 高(每段文字都要标注"哪些 token 可被 AI highlight")。
- 用户可能根本意识不到 AI 在工作 —— "AI 在 dim 一段你正在读的字"可能被当成 bug。

**给 Orchestrator 的决策点**:
1. **AI 的核心价值是"提供内容"还是"管理注意力"?** v1-v3 都押前者,这版押后者。这是元命题。
2. 如果在 v3 之后留一个真激进版做对照测试,愿意花 1 周做这个吗?

### 提案 R2-B · 砍掉"我开口"频道,改成"用户写完一句话后 4 秒内必有回声"(中度激进 · 最辣)

**核心想法**(≤ 30 字):
AI 不主动,但用户写完就被听见。

**最辣的设计实现细节**:
- 删除全部 8 个"我开口"。AI **完全**不主动 surface。
- 用户每次在 note 区写完一段(blur textarea 或停止输入 ≥ 4 秒),AI **必有**一个 ≤ 15 字的回声出现在该 note 下方。
- 回声**不是 LLM**(0 RAG,且离线),是**纯 client-side 规则**:
  - 用户写到"葬" → 回声"(3 + 2 + 1 + 羊驼。)"
  - 用户写到"精灵" → 回声"(原文是 espíritu。)"
  - 用户写到"玉" → 回声"(玉米。)"
  - 用户写的内容没匹配任何关键词 → 回声"。"(就一个句号。表示"听到了。")
- 回声**不是对话**——用户**不能**继续问 AI。回声是单次 echo,出现 6 秒后自动 fade 到 var(--faint),永久保留为该 note 的小尾巴。
- 整个 4 小时,AI 没有任何主动行为。只有:**你说了 → 我点头一次**。
- intro 段照旧(必须有"今天玉会反复出现"这种 setup,但用 system 字体不用 ai-speak 块,**不属于"AI 开口"**)。

**它 reframe 了什么**:
- v1: 9 次开口剧本。v2: 8 + 4 = 12 块剧本。v3: 6-8 次动态剧本。本提案:**0 次主动剧本,纯被动 echo**。
- 直接挑战 PRD §6 "立场":AI 没有立场,AI 只有耳朵。
- **完全**遵守原则 B(反讲解员)—— 物理上无法讲解。
- 部分质疑产品的"AI 同伴"命题:同伴**真的需要主动开口吗**?还是"被听见"已经是 80% 价值?
- 这版本质是把"AI 同伴"重定义为"**回音壁同伴**"——他不发言,他只确认"你的话落到了一个地方"。

**风险 / 反对意见**:
- 测不到"内容"——所有关于玉 / 1987 / 同葬 / 精灵翻译的**立场内容**全没了。如果项目的核心命题是"AI 能不能传递克制的立场",这版直接跑题。
- 关键词触发的回声是脆弱的——用户写"陪着妈妈"也会触发"葬"族关键词的误判(其实"陪"在死亡语境的概率高,但你也可能写"陪老婆")。需要**很小心**的词表设计,而且一定有翻车。
- 4 小时 8 个 note 段 × 平均 12 字 = **AI 一共说了不到 100 字**——这是一个测**信息密度极低**的同伴版本,可能让用户觉得"AI 没存在"。
- 但反过来:**正因为 AI 没存在,用户才"想念"AI**。这是 v1/v2/v3 都拿不到的体感——能不能"想念"是 PRD §6 没显式提的人格指标。
- 离讲解员最远,**也离讲解员的反面"知识载体"最远**——可能两头都不靠。

**给 Orchestrator 的决策点**:
1. **如果做一个并行 dogfood(同一个用户先走 v3,3 天后走这版),你想看哪个体验在"3 天后回忆里"留下更多?** 这是哲学问题,值得花一次实地测试。
2. 关键词→回声的词表,需要 PM 亲自定(立场都压在词表里)—— 愿意花 2 小时做吗?

### 提案 R2-C · 把"测试用户作为受试者"这件事 surface 出来:产品里多一个频道"研究员视角"(轻激进)

**核心想法**(≤ 30 字):
不再假装用户不知道这是 dogfood。

**最辣的设计实现细节**:
- 顶部 header 多一个 chip:`研究员模式 [开 / 关]`。**默认开**(因为用户本来就是团队成员,假装没用)。
- 开着时,每个触点除了原本的 ai-speak + user action,**额外**有一个 collapsed 的 `<details>` 块:"为什么是这一刻 / 这句话 — 团队的设计理由"。点开是 50-100 字的内部 note:
  - 玉那段下面:"我们想测的是:玛雅符号系统能不能在 30 秒内被一句话压成可携带的形式。如果你看完这段没记住'玉米'两个字,这段就失败了。"
  - 1987 那段下面:"我们犹豫过要不要在第一次开口就提盗墓——可能太重。最终决定提,因为'是从盗墓贼手里抢回来的'是这段历史的真实状态。如果你觉得突兀,告诉我们。"
- 关闭研究员模式后,产品退化为 v3 的样子(纯用户视角)。
- export team 反馈时,**自动把"开着研究员模式的那些段"做成 A/B 对照**——"这一段你是带着设计理由读的,还是纯体验的?"

**它 reframe 了什么**:
- 当前所有版本(v1 / v2 / v3)都假装用户是"普通用户"。但 5/18 实地测的真实情境是:**用户 = 团队成员 = 林知白同 cluster 的 PM**。**这个事实被产品隐藏了**。
- 这版承认 dogfood 的本质,**把"产品 + 元产品"折叠成同一个产品**。
- 直接挑战 PRD §6 的"克制人格唯一性"——这版有两层人格:对外的克制 AI + 内部的诚实研究员。
- 服务于一个 v1/v2/v3 都没服务好的目标:**让 dogfood 的反馈质量提一个档**——团队成员带着设计理由测,比当作普通用户测,反馈密度更高。

**风险 / 反对意见**:
- 破坏"沉浸"——克制美学和"看后台"是冲突的。一旦开了研究员模式,产品就不再"看起来像产品",像 figma 评审。
- 如果以后给外部用户用,这个模式必须能彻底关掉(也确实可以,但工程上多一层维护)。
- "设计理由"文本本身是新内容工作量,而且如果写得不诚实(写成 PR 稿),反而更糟。
- 团队成员看了设计理由再读 ai-speak,**很难再当作普通用户体验**——A/B 对照里"开着研究员模式的段"的反馈天然带偏。

**给 Orchestrator 的决策点**:
1. **5/18 这次测试,要不要诚实承认"我们就是在 dogfood"?** 如果承认,这版有用;如果还想伪装成"用户实测",这版破坏假象。
2. 研究员模式如果只用在 1-2 个最难的触点(例如 1987 盗墓 + 同葬),而不是全开,作为"重点段调试灯",愿意做吗?

## meta · 这 3 个新提案 + v3 骨架的押注分布

| 方向 | 押什么 | 风险 |
|---|---|---|
| **v3 骨架(R1#3 落地)** | AI 的核心价值在"时序感" + "negative space" | 状态机复杂度 / 用户读不懂 AI 状态 |
| **R2-A(高亮代替开口)** | AI 的核心价值在"注意力管理"而非"信息供给" | 测不到内容立场 / 视觉脆弱 |
| **R2-B(回声壁)** | AI 的核心价值在"被听见"而非"主动说" | 完全跑题 / 但拿到"想念"指标 |
| **R2-C(研究员模式)** | dogfood 本质必须 surface | 破坏沉浸 / 但提反馈密度 |

**如果只能再加 1 个并行实验**(在 v3 之外):
- 我倾向 **R2-B(回声壁)**——它最直接挑战"AI 同伴必须主动"这个深层假设,且实现成本最低(就是个关键词词表 + textarea blur 监听)。一次 4 小时实测能拿到 v1/v2/v3 拿不到的指标:**用户对"沉默 AI"的容忍度 / 想念度**。

**如果 Orchestrator 觉得 v3 已经够辣**:那 R2-B 留到 R3 再起。但 R2-C(研究员模式)**强烈建议在 v3 里至少做 2 个触点的版本**——dogfood 第一次实测,把"为什么是这句话"的设计理由 surface 给团队用户,**几乎零风险高回报**。

**最值得 PM 拍板的元问题**:
> v2 用结构 narrate 了立场("看,我克制";"看,我引用了你 anchor")。v3 要避免再 narrate——但**到底是用"显式状态吊牌"让 AI 状态可见**(避免误判 AI 故障),**还是干脆让 AI 状态完全不可见**(真正的 negative space)?
>
> 前者安全。后者更诚实。两者不能同时存在。
